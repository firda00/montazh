# ТЗ: ИИ-агент для видеомонтажа (MVP)

> Документ для Claude Code. Положи его в корень репозитория как `SPEC.md` (или `CLAUDE.md`) и попроси: «Прочитай SPEC.md и реализуй MVP по этапам».

## 1. Суть продукта

Пользователь загружает сырое видео и пишет инструкцию обычным текстом, например «сделай 3 рилса по 30 секунд для моего кафе, динамично, с субтитрами на узбекском». Агент **смотрит видео** и понимает, что в кадре, что говорят и где лучшие моменты. Затем сам принимает решения по монтажу, режет, оформляет и отдаёт готовые MP4. Правки идут диалогом: «ускорь начало», «убери второй кусок».

**Главное отличие от Captions и CapCut:** монтаж строится на понимании картинки и смысла, а не только на транскрипте и паузах.

## 2. Цели MVP

1. Видео → понимание: таймлайн сцен, транскрипт, лучшие моменты.
2. Инструкция пользователя → план монтажа (EDL в JSON).
3. План → нарезка исходника (FFmpeg).
4. Оформление: анимированные субтитры, титры, интро и аутро (HyperFrames и/или Remotion).
5. Экспорт MP4 в 9:16, 1:1 и 16:9.
6. Правки диалогом: изменить план и перерендерить.

**Не входит в MVP:** веб-интерфейс с таймлайном, мультиюзерность, биллинг, мобильное приложение, генерация видео с нуля.

## 3. Архитектура пайплайна

```
[Исходное видео]
      │
      ▼
1. INGEST         — ffprobe, нормализация (fps, разрешение), извлечение аудио
      │
      ▼
2. UNDERSTAND     — транскрипт с таймкодами (слова) + мультимодальный анализ кадров
      │               → scenes.json, transcript.json, highlights.json
      ▼
3. PLAN (агент)   — LLM получает инструкцию + результаты анализа → edl.json
      │
      ▼
4. CUT            — FFmpeg режет/склеивает по edl.json → rough_cut.mp4
      │
      ▼
5. DESIGN         — генерация оверлеев (субтитры, титры, плашки) через
      │               HyperFrames/Remotion + дизайн-скиллы → overlay-композиция
      ▼
6. RENDER         — финальный рендер → output_*.mp4
      │
      ▼
7. REVISE         — правка пользователя → агент меняет edl.json/дизайн → шаг 4–6
```

Каждый шаг — отдельный модуль с JSON-входом и JSON-выходом. Шаги можно перезапускать по отдельности, промежуточные результаты кэшируются в `workspace/<job_id>/`.

## 4. Технологический стек

| Слой | Технология | Примечание |
|---|---|---|
| Язык | TypeScript (Node 20+) | Remotion и HyperFrames живут в JS-экосистеме |
| Нарезка | FFmpeg / ffprobe | через `child_process` или `fluent-ffmpeg` |
| Транскрипция | Whisper (OpenAI API или локальный whisper.cpp) | нужны таймкоды на уровне слов; языки: uz, ru, en |
| Понимание видео | Gemini (мультимодальный, умеет видео) | сцены, объекты, эмоции, «лучшие моменты» |
| Агент-оркестратор | Claude API (tool use) | строит и правит план монтажа |
| Графика / рендер | **HyperFrames (HeyGen)** — HTML → MP4; **Remotion** — React → MP4 | начать с одного (см. п. 9), второй как альтернатива |
| Дизайн-скиллы | **Impeccable** (pbakaus/impeccable), **taste-skill** (Leonxlnx), **emilkowalski/skills** | подключаются как скиллы/промпт-гайды для генерации оверлеев |
| Валидация | zod | схемы для всех JSON |
| CLI | commander | интерфейс MVP |

**Важно для Claude Code:** перед интеграцией HyperFrames, Remotion и скиллов прочитай их актуальные README и документацию в репозиториях. Не угадывай API.

## 5. Модули и контракты данных

### 5.1 `ingest`
- Вход: путь к видео.
- Выход: `media.json` с длительностью, fps, разрешением, аудиодорожкой и путём к нормализованной копии.

### 5.2 `understand`
- `transcript.json`: `[{ start, end, text, words: [{ w, start, end }] }]`, язык определяется автоматически.
- `scenes.json`: `[{ start, end, description, objects[], people_count, emotion, shot_type, quality_score }]`.
- `highlights.json`: `[{ start, end, reason, score }]`. Это лучшие моменты с объяснением, почему.
- Длинное видео резать на чанки (например, по 2–5 минут) для анализа, потом склеивать результаты.

### 5.3 `plan` (агент)
- Вход: инструкция пользователя + `transcript` + `scenes` + `highlights` + пресет стиля.
- Выход: `edl.json`

```json
{
  "outputs": [
    {
      "id": "reel_1",
      "aspect": "9:16",
      "target_duration": 30,
      "clips": [
        { "src_start": 12.4, "src_end": 17.9, "speed": 1.0, "crop": "auto_face" }
      ],
      "captions": { "enabled": true, "language": "uz", "style": "bold_pop" },
      "titles": [{ "at": 0, "text": "Лучший плов в городе", "style": "hero" }],
      "music": { "enabled": false },
      "transitions": "cut"
    }
  ],
  "reasoning": "почему выбраны эти куски"
}
```

- Агенту доступны инструменты (tool use): `get_transcript_range`, `get_scene_details`, `preview_frame(timestamp)`, `validate_edl`.
- Правило: каждый клип должен начинаться и заканчиваться на границе фразы или сцены, без обрезанных слов.

### 5.4 `cut`
- FFmpeg по `edl.json`: обрезка, скорость, кроп под формат (для 9:16 — кроп с удержанием лица в кадре), склейка.
- Выход: `rough_<id>.mp4`.

### 5.5 `design`
- Генерирует оверлеи по `edl.json` и транскрипту: анимированные пословные субтитры, титры, плашки, интро и аутро.
- Генерация HTML/React-кода оверлеев идёт через LLM с подключёнными скиллами Impeccable, taste-skill и emilkowalski/skills. Это нужно, чтобы графика выглядела дорого, а не шаблонно.
- Стиль задаётся пресетом (`presets/*.json`): шрифты, цвета, анимации, позиции.

### 5.6 `render`
- Композиция `rough cut` + оверлеи → финальный MP4 (H.264, AAC, -14 LUFS).
- Выход: `output_<id>.mp4` + превью-кадр.

### 5.7 `revise`
- Вход: текстовая правка + текущий `edl.json`.
- Агент возвращает изменённый `edl.json` и diff. Перерендер идёт только для затронутых выходов.

## 6. Интерфейс MVP (CLI)

```bash
vedit run ./raw.mp4 --prompt "3 рилса по 30 сек, динамично, субтитры на узбекском" --preset bold_pop
vedit revise <job_id> --prompt "в reel_2 убери первые 3 секунды и сделай титр крупнее"
vedit status <job_id>
```

## 8. Требования к качеству

- Видео до 10 минут обрабатывается до готового результата за ≤ 5 минут (ориентир).
- Ни один клип не обрывает слово на середине.
- Субтитры синхронны с речью (расхождение ≤ 100 мс).
- В кадре 9:16 говорящий человек не «уезжает» за край.
- Логирование стоимости API-вызовов на каждую задачу (`cost.json`). Важно для юнит-экономики.
- Все JSON валидируются схемами, ошибки шага не роняют весь пайплайн.

## 9. Этапы разработки

1. **Каркас:** структура репо, CLI, схемы, `ingest` + `cut` по вручную написанному `edl.json`.
2. **Понимание:** транскрипция + анализ видео через Gemini → `scenes`, `highlights`.
3. **Агент-планировщик:** Claude с tool use строит `edl.json` из инструкции.
4. **Оформление:** субтитры и титры. Сначала прототип на HyperFrames и Remotion, выбрать один по качеству и скорости рендера. Подключить дизайн-скиллы.
5. **Правки диалогом** (`revise`).
6. **Тесты на 10 реальных видео** (кафе, блогер, эксперт, товар), фиксация проблем.
7. **Telegram-бот** как первый пользовательский интерфейс.

После каждого этапа: рабочая демонстрация на тестовом видео из `/tests/fixtures`.
