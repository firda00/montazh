# vedit — ИИ-агент для видеомонтажа (MVP)

Спецификация: [SPEC.md](SPEC.md). Требуется Node 20+ и ffmpeg/ffprobe в PATH.

```bash
npm install
npm run fixtures            # тестовые видео с таймкодом в кадре → tests/fixtures/
npm test
```

## Этап 1 — каркас: ingest + cut по ручному edl.json

```bash
node bin/vedit.mjs run tests/fixtures/timecode_60s_1080p25.mp4 --edl tests/edl/demo_three_formats.json
node bin/vedit.mjs status <job_id>
node bin/vedit.mjs cut <job_id> [--edl new.json] [--only reel_1]
npx tsx tests/contact-sheet.ts <job_id>   # первый/последний кадр каждого клипа для проверки
```

Всё по задаче лежит в `workspace/<job_id>/`: `job.json` (статусы шагов), `media.json`,
`normalized.mp4` (CFR 30fps, H.264/AAC, всегда с аудио), `audio.wav` (16 kHz для Whisper),
`edl.json`, `cut.json`, `rough_<id>.mp4`, `cost.json`.

## Этап 2 — понимание: транскрипт, сцены, лучшие моменты

```bash
node scripts/setup-whisper.mjs      # whisper.cpp + ggml-large-v3-turbo-q5_0 (574 MB) → vendor/whisper/
node bin/vedit.mjs run tests/fixtures/cafe_speech_ru_en.mp4           # ingest → understand
node bin/vedit.mjs understand <job_id> [--language ru] [--method dtw|tokens] [--threads 16]
node bin/vedit.mjs cut <job_id> --edl tests/edl/demo_speech.json [--no-snap]
npx tsx tests/eval-transcript.ts <job_id>   # точность пословных таймкодов против .truth.json
```

Результаты в `workspace/<job_id>/`: `transcript.json` (фразы и слова с таймкодами, язык
каждой фразы), `scenes.json`, `highlights.json`, `frames/shot_NNN.jpg`, `understand.json`
(отчёт), `whisper/chunk_N.json` (сырой вывод whisper).

Как это устроено:

- **Транскрипция** — локальный whisper.cpp. Аудио режется на куски по паузам (`silencedetect`),
  каждый кусок ≤ 28 с (whisper кодирует окна по 30 с, кусок короче окна стоит столько же),
  язык определяется на каждом куске отдельно — смешанные ru/en/uz видео работают.
  Пословные таймкоды через DTW (`-dtw`): на тестовом ролике медиана ошибки 40 мс, p90 135 мс.
  Встроенный VAD whisper **не используется**: он сдвигает таймкоды токенов. Известные
  галлюцинации («Редактор субтитров…») отфильтровываются.
- **Сцены** — границы шотов через `select=gt(scene,0.2)` в ffmpeg + кадр из середины каждого шота.
- **Vision** — интерфейс `VisionProvider`, три провайдера (`src/understand/vision/`); выбор: `--vision auto|gemini|agy|stub`
  или `VEDIT_VISION=…`; `auto` = ключ Gemini → Antigravity CLI, если установлен → stub:
  - `gemini` (включается, когда в `.env` есть `GEMINI_API_KEY`; модель по умолчанию `gemini-2.5-flash-lite`,
    меняется через `VEDIT_VISION_MODEL`, разрешение кадра — `VEDIT_VISION_RESOLUTION=low|medium|high`).
    Каждый чанк (≤ 5 мин, по границам шотов) перекодируется в немой ролик 360p/2 fps (речь уже в транскрипте),
    уходит inline (до 15 МБ) или через Files API, модель отвечает строгим JSON (`responseSchema`): описание
    **каждого** шота по индексу, объекты, люди, эмоция, тип плана, качество, точка фокуса (лицо/предмет) и до
    8 highlights. Пропущенные моделью шоты помечаются «(not described by the model)», а не выдумываются.
    Стоимость считается по таблице цен и пишется в `cost.json` (неизвестные модели — `unpriced`); 10 минут видео
    на flash-lite ≈ $0.02–0.05.
  - `agy` — **без ключа API**, через Antigravity CLI (`agy`, вход Google-аккаунтом, как планировщик через вход
    Claude Code). Картинки в CLI не передать, поэтому агенту даются кадры шотов (`frames/shot_NNN.jpg`, уже
    извлечены на этапе сцен), он открывает их своим просмотрщиком файлов и отвечает JSON по `--json-schema`
    (та же схема, что у Gemini API). Один вызов на чанк, ~40–90 с (у CLI системный промпт ≈20k токенов);
    модель по умолчанию `gemini-3.8-flash-low`, список — `agy models`. Стоимость 0 (подписка), токены пишутся
    в `cost.json`. Минус: по одному кадру на шот — движение внутри шота модель не видит.
  - `stub` (без ключа или `--vision stub`): описания помечены `[stub]`, людей/эмоций не выдумывает,
    highlights ранжирует по измеримому (целая фраза, длина, громкость).
- **auto_face** — точки фокуса от Gemini (`scenes[].focus`) задают кроп: для каждого клипа с
  `crop: "auto_face"` окно 9:16 центрируется на средневзвешенной (по перекрытию шотов) точке и не выходит за
  кадр; один статичный кроп на клип, без дрожания. Без данных о фокусе — центр-кроп с предупреждением.
- **Границы слов** — `cut` проверяет края клипов по транскрипту и по умолчанию подтягивает их
  к границе слова (сдвиг ≤ 0.4 с), иначе предупреждает.

Грабли Windows: whisper-cli падает (0xC0000409), если путь к **модели** содержит не-ASCII
символы — поэтому процесс запускается из папки модели. Скорость на CPU (i7-13700, 16 потоков)
≈ 1–2× реального времени.

## Этап 3 — агент-планировщик (инструкция → edl.json) и правки диалогом

```bash
node bin/vedit.mjs run tests/fixtures/cafe_long_ru.mp4 -p "3 рилса по 30 секунд для кафе, динамично, субтитры на узбекском"
node bin/vedit.mjs plan <job_id> -p "…" [--preset bold_pop] [--cut] [--dry-run] [--backend auto|api|agent|mock] [--effort medium] [--budget 1.5] [--verbose]
node bin/vedit.mjs revise <job_id> -p "в reel_3 убери приветствие и добавь фразу про самсу" [--no-cut]
node bin/vedit.mjs status <job_id>
```

Как это устроено (дизайн: [docs/stage3-design.md](docs/stage3-design.md)):

- **Пакет контекста** — все фразы `pN`, сцены `sN`, паузы `gN`, highlights `hN` одним детерминированным
  JSON (~3k токенов на 2-минутное видео, ~15k на 10 минут). Он кэшируется и переиспользуется в
  ремонтах и правках.
- **План по ссылкам, а не секундам** — клип `{start:"p3", end:"p5"}`; граница фразы/сцены гарантирована
  конструкцией (ТЗ §5.3). Резы в паузе `gN` и по границе слова `pN.wK` разрешены с предупреждением.
- **Валидация на нашей стороне** (`src/plan/resolve.ts`): неизвестные ссылки, пустые клипы, скорость
  поверх речи, длительность ±10 % (жёстко ±25 %), слова целиком, число выходов, титры. Ошибки уходят
  модели списком, ≤ 2 исправлений; выходы без ошибок сохраняются даже если другие отброшены.
- **Инструменты** (ТЗ): `get_transcript_range`, `get_scene_details`, `preview_frame`, `validate_edl` —
  объявлены всегда, модель вызывает их по необходимости (на фикстуре — ни разу: пакета хватает).
- **Бэкенды**: `api` — Claude API через SDK (`ANTHROPIC_API_KEY`); `agent` — Claude Agent SDK, то есть
  вход Claude Code по подписке, выбирается автоматически без ключа; `mock` — эвристика для тестов
  (план помечен `[mock]`, никогда не выбирается сам). Модель `claude-opus-5-5`, effort `medium`.
- **Лимиты на одно планирование**: $1.50, 240 с, 12 запросов, 2 исправления, 6 превью-кадров.
- **Правки** (`revise`, этап 5 со стороны плана): текущий план показывается модели ссылками, меняется
  только запрошенное, `edl.vN.json` — бэкап, `revise.json` — diff, перерезаются только затронутые выходы.
- **Стоимость** пишется в `cost.json` по каждому запросу; для `agent` это оценка SDK (`≈$`), не счёт.

Измерено на `cafe_long_ru.mp4` (114 с, 20 фраз) через подписку: план — 1 запрос, 86 с, ≈$0.19;
правка — 1 запрос, 50 с, ≈$0.11. Ремонт через `resume` сессии CLI стоил ≈$1.1 (перезаливка транскрипта),
поэтому ремонты и правки идут новой сессией с тем же префиксом (`VEDIT_AGENT_RESUME=1` возвращает resume).

## Этап 4 — оформление и финальный рендер

```bash
node bin/vedit.mjs run video.mp4 -p "3 рилса по 30 секунд, субтитры на узбекском"   # … → cut → render
node bin/vedit.mjs render <job_id> [--only reel_1] [--quality draft|looks|delivery] [--workers 3] [--no-translate]
```

Результат: `workspace/<job>/output_<id>.mp4` (H.264 bt709 + AAC, −14 LUFS, длина = черновой нарезке),
`output_<id>_preview.jpg`, `render.json`; проект оверлея — `design/<id>/` (`index.html`, `layout.json`, `lint.json`, `render.log`).

Как это устроено (исследование и прототипы: [docs/stage4-research.md](docs/stage4-research.md), [docs/stage4-prototypes.json](docs/stage4-prototypes.json)):

- **Рендерер — HyperFrames 0.8.145** (Apache-2.0, pinned devDependency, вызывается локальный `bin`, телеметрия
  выключена, GSAP и шрифт вендорены — сеть при рендере не нужна). Remotion прототипирован и отвергнут:
  бесплатен только при ≤ 3 сотрудниках, иначе $0.01/рендер с минимумом $100/мес; исходники — `tools/remotion-overlay/`.
- **Таймлайн** (`src/design/timeline.ts`): слова транскрипта переносятся на шкалу выхода через клипы EDL (с учётом
  скорости), фразы режутся по стыкам.
- **Перевод субтитров** (`src/design/translate.ts`): если язык субтитров в плане отличается от речи — фразы
  переводятся одним структурированным вызовом Claude (через ключ или вход Claude Code), кэш `translations_<lang>.json`,
  слова раскладываются по времени фразы пропорционально длине.
- **Раскладка** (`src/design/layout.ts`): реальные ширины из TTF (opentype.js, Inter wght 800, сверено с Chrome
  с точностью 1–2 %), страницы ≤ 4 слов без висячих служебных слов, сбалансированные двухстрочные разрывы,
  запас на «поп» активного слова, окна показа с удержанием через короткие паузы.
- **Композиция** (`src/design/hyperframes/compose.ts`): одна standalone-композиция, `<video muted>` без звука,
  страница субтитров = timed `<section class="clip cap caption-group">`, один paused GSAP-таймлайн,
  твины только на внутренних span'ах; lint-гейт перед рендером.
- **Финализация** (`src/render/finalize.ts`): видео оверлея копируется без перекодирования, звук берётся из
  черновой нарезки и нормализуется в два прохода `loudnorm` до −14 LUFS, длина обрезается до черновика.
- **Воркеры** считаются от свободной памяти (≈320 МБ на Chrome-воркер + 1 ГБ запас); на машине с 8 ГБ RAM
  это 1–3 воркера.

Измерено (reel_1, 19,9 с, 1080×1920): 56 с на 1 воркере при 1 ГБ свободной памяти (прототип на 3 воркерах — 45 с).
На Windows HyperFrames всегда захватывает кадры скриншотами (~17 fps при 3 воркерах); на Linux доступен более
быстрый путь `beginframe` — продовый рендер стоит планировать там.

## Этап 7 — Telegram-бот

Первый пользовательский интерфейс: прислать видео → написать задачу → получить готовые MP4.

1. Создайте бота у [@BotFather](https://t.me/BotFather): `/newbot` → имя → username, скопируйте токен.
2. Узнайте свой числовой user id (например, у @userinfobot) и пропишите в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC…
   TELEGRAM_ALLOWED_USERS=111111111,222222222
   ```
   Без `TELEGRAM_ALLOWED_USERS` бот отвечает всем — а каждый монтаж тратит деньги на планировщик.
3. `npm run bot` (long polling, вебхук и публичный адрес не нужны; логи в stdout, Ctrl+C — остановить).

В чате: видео (как видео или файлом `video/*`; подпись к видео сразу считается задачей) → текст задачи →
бот запускает тот же пайплайн, что `vedit run` (ingest → understand → plan с пресетом `bold_pop` → cut → render
HyperFrames), присылает прогресс («▸ анализ речи…», «▸ план…» со сводкой плана, «▸ рендер reel_1 (1/3)…») и
по сообщению на каждый `output_<id>.mp4` с подписью (id, длительность, выдержка из reasoning планировщика).
Команды: `/start` — справка, `/status` — последняя задача, `/revise <что изменить>` — правка (перерезаются и
перерендериваются только затронутые выходы), `/cancel` — отмена после текущего шага. Один монтаж на чат
одновременно. Ошибки планировщика приходят с теми же подсказками, что в CLI; бот при ошибках не падает.

Лимиты облачного Bot API: бот скачивает файлы **до 20 МБ**, отправляет **до 50 МБ**. Видео больше — присылается
**ссылкой** (Google Диск, Яндекс Диск, Dropbox, YouTube…, см. «Этап 24»); готовый ролик больше 50 МБ бот сжимает или
присылает путь к файлу на сервере. Снять лимиты (до 2000 МБ) можно локальным сервером
[telegram-bot-api](https://github.com/tdlib/telegram-bot-api) с флагом `--local` и
`TELEGRAM_API_BASE=http://127.0.0.1:8081` (на сервере — `deploy/telegram-bot-api.sh`, см. «Этап 24»).

Состояние (до этапа 19): `workspace/_bot/<chat>/<file_id>.mp4` (исходники), `workspace/_bot/state.json` (чат → исходник,
задача, промпт; offset getUpdates). С этапа 19 всё это в SQLite `workspace/_bot/vedit.db`, а `state.json` переносится
туда при первом запуске (см. «Пользователи, кнопки, лимиты»). Код: `src/bot/telegram-api.ts` (клиент Bot API на
`fetch`/`FormData`, без зависимостей, повтор 429 по `retry_after`), `src/bot/index.ts` (цикл бота), `src/bot/run.ts`.

## Длинное видео: faster-whisper, говорящие, отбор моментов

Часовой ролик на 15 ГБ не пройдёт через Telegram (лимит 20 МБ, с локальным Bot API 2 ГБ) — его обрабатывает CLI:

```bash
node bin/vedit.mjs run D:/видео/podcast.mp4 -p "10 рилсов по 30 секунд, самые сильные мысли" --speaker 12:34
```

Что добавлено (этап 8):

- **Python-сайдкар `tools/asr/vedit_asr.py`** (venv в `tools/asr/.venv`): установка —
  `python -m venv tools/asr/.venv && tools/asr/.venv/Scripts/pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu && tools/asr/.venv/Scripts/pip install faster-whisper speechbrain scipy`
  (на сервере с NVIDIA — обычный `torch` с CUDA). Лицензии: faster-whisper/CTranslate2 (MIT), веса Whisper (MIT),
  SpeechBrain и веса ECAPA (Apache-2.0). Модели качаются при первом запуске в `tools/asr/models/` (~1.7 ГБ).
- **Движок речи `--asr auto|cpp|faster`** (`VEDIT_ASR`). `auto` берёт faster-whisper при наличии NVIDIA GPU
  (`nvidia-smi` в PATH) или для файлов длиннее 20 минут даже на CPU: whisper.cpp грузит модель на каждый 28-секундный
  кусок (327 загрузок на 2 ч), faster-whisper — один раз. На коротком файле на CPU он не быстрее whisper.cpp
  (8 с аудио — 37 с против 32 с на i7-13700), а whisper.cpp
  определяет язык на каждом куске речи, что нужно смешанным ru/uz видео; faster-whisper определяет язык один раз на файл
  (английскую фразу в ru-ролике он перевёл на русский). На GPU от 4 ГБ faster-whisper делает час речи за 3–5 минут.
  Сырой вывод — `whisper/faster.json`; WAV читается самим сайдкаром (PyAV-путь faster-whisper ломается между версиями).
  Кусок, на котором whisper-cli упал, повторяется один раз, затем распознаётся faster-whisper (если сайдкар установлен);
  такой кусок помечен `engine: "faster-whisper"` в `whisper/chunks.json`.
- **Говорящие** (`speakers.json`, `speaker` у каждой фразы): эмбеддинг ECAPA-TDNN на фразу + агломеративная кластеризация
  по косинусному расстоянию (порог 0.72, или `--speakers N`); кластеры короче 10 с речи или из < 3 фраз (смех, междометия)
  сливаются с ближайшим по центроиду (`--min-cluster-seconds` сайдкара, проверка — `vedit_asr.py selftest`).
  S1 — тот, кто говорит больше всех. Это разметка **по фразам**:
  фраза, где перебивают, получает одного говорящего. Отключить — `--no-diarize` / `VEDIT_DIARIZE=0`. На фикстуре с двумя
  SAPI-голосами: 6 русских фраз → S1, английская → S2, 5 с на CPU.
- **Нарезки одного человека** — `--speaker S2`, `--speaker 12:34` (кто говорит в этот момент) или `--speaker most`:
  в пак планировщика попадают только его фразы (и highlights, которые их касаются), промпт получает `SPEAKER: only S2…`.
  `revise` переиспользует тот же фильтр из `plan.json`, иначе ссылки pN разъехались бы.
- **Режим длинного видео** (`--long` / `--no-long`, по умолчанию — когда фраз > 250 или пак > 60k токенов): сначала
  дешёвый structured-вызов по индексу «одна строка на фразу» (`pN mm:ss S1 ru: текст…`, ~25 токенов на фразу, час речи ≈
  22k токенов ≈ $0.05–0.1 на Opus) выбирает до 24 окон-кандидатов под инструкцию; окна расширяются до целых фраз
  с контекстом ±1 фраза, длинные режутся по 120 с. Больше 2000 фраз — индекс уходит двумя вызовами по половинам
  (окна делятся пропорционально, стоимость суммируется). Планировщик видит пак в режиме `shortlist`: только фразы, сцены,
  паузы и highlights внутри окон, список `windows` и счётчик `omitted`. Без модели (или при её ошибке) окна берутся
  из топа highlights. Стоимость шортлиста пишется в `cost.json` (`shortlist: 1`).

Оценка для часа речи на этой машине (CPU): перекодирование 20–30 мин, whisper.cpp 40–60 мин, говорящие ~5–10 мин,
vision через agy ~10–15 мин, шортлист + план 2–4 мин, рендер ~1 мин на 30-секундный рилс. На сервере с GPU — минус
час на распознавании. Не проверено на реальном часовом ролике: нужен файл.

## Ролик из ничего: `vedit make` и `/make` (этап 10)

Тема → готовый вертикальный ролик без исходного видео и без голоса: текст, иконки, моушн-графика.

```bash
node bin/vedit.mjs make "почему кофе дорожает в 2026 году" --seconds 35 [--lang uz] [--music track.mp3] [--no-trends]
node bin/vedit.mjs make "…" --script workspace/<job>/script.json      # перерендерить сохранённый сценарий
```

Конвейер (`src/make/`): **тренды** — агент Antigravity CLI ищет в вебе и читает страницы, отдаёт факты с
источниками, углы, хуки и что не повторять (`trends.json`, ~1–2.5 мин, $0; без agy шаг пропускается) →
**сценарий** — structured-вызов Claude по `prompts/make.script.*`: заголовок, 4–8 битов по одному предложению
с подчёркиваемым словом, иконкой Lucide и длительностью (не короче скорости чтения ≈2.6 слов/с), факты только из
трендов (`script.json`, ≈$0.05) → **композиция** HyperFrames (`src/make/compose.ts`): градиентный фон с медленным
бликом, кикер-тема, одна секция на бит с иконкой и текстом, размер шрифта подбирается по реальным метрикам Inter
так, чтобы строки влезали в 82% ширины (≤3 строк), слова поднимаются по очереди, акцентные слова подсвечиваются,
прогресс-бар; детерминированный HTML, lint CLI без ошибок → **рендер** → `output_make.mp4`
(+ `--music`: зацикленная подложка, −14 LUFS, затухание). Отчёт `make.json`, стоимость в `cost.json`.

**Арт-директор (этап 10b).** Вместо одного шаблона модель (`prompts/make.design.*`, `src/make/design.ts`) решает
айдентику ролика: палитру, пару шрифтов (Inter / Unbounded / Playfair Display + курсив Playfair / JetBrains Mono —
все OFL с кириллицей, `src/make/fonts.ts`), текстуру (зерно, сетка, свечение), единый стиль картинок и бренд-метку,
а для каждого бита — свою композицию из словаря: огромная цифра с градиентом, редакционный заголовок, фото на весь
кадр, фото-карточка со свечением, сплит, список, чат, таймлайн, сравнение, цитата; акценты (маркер, цвет, курсив
с засечками, градиент, обводка) и вход текста (подъём, маска, поп, печать, слайд). Правила: не повторять макет
подряд, 4+ разных макета, 2–4 кадра с картинками, хук — самый сильный кадр. Картинки генерирует инструмент
изображений Antigravity по промптам директора (`src/make/images.ts`, 2 картинки ≈ 2 мин, $0) и нормализует в
1080×1920. Сцены собирает `src/make/scenes.ts`, текст подгоняется по рамкам в настоящем headless Chrome с реальными
шрифтами (`src/make/fit.ts`, puppeteer-core из зависимостей HyperFrames). После рендера — контактный лист кадров
`make/sheet.jpg`. Перерендер без новых запросов: `vedit make "<тема>" --from <job>`; простая версия:
`--no-director` (только 9:16), без картинок: `--images none` (или `--no-images`). Все макеты на одной картинке: `tools/make-layouts-demo.ts`.

**3D-графика кодом (этап 10c).** Ещё три макета на CSS 3D (без WebGL: заголовок и объекты в одной сцене, поэтому
кубы честно заходят за буквы, а текст проходит через подгонку в Chrome): `orbit_title` — огромный заголовок в
кольце из 32 вращающихся кубов, `depth_cards` — 3–4 карточки на разной глубине, камера пролетает сквозь них и
подсвечивает каждую по очереди, `tunnel_number` — большая цифра вылетает из перспективного туннеля-сетки. Вся
геометрия считается в Node от сида (детерминированный рендер), 1–2 таких бита на ролик, лучше всего как хук.
Неподходящие данные понижаются до обычных макетов (`normalizeDesign`). Кадр 3D ≈ 1.5× дороже обычного в рендере.
Только 3D-макеты: `npx tsx tools/make-layouts-demo.ts --3d`.

Живой прогон: «почему кофе дорожает в 2026 году» — тренды 147 с (5 фактов с источниками tradingeconomics,
bcs-express, tbank), сценарий $0.064, рендер 93 с, итог 35 с, 7 битов. В Telegram: `/make тема`.
Лицензии: Lucide ISC, остальное как у рендера. Чего пока нет: сток Pexels и YouTube Data API (ждут ключей),

- **Сценарий без клише.** `prompts/make.script.*` запрещает «не X, а Y», «дело не в…», «давайте разберёмся»,
  «представьте», «в мире, где», «это не просто», «вот почему», тире-панчлайны, риторические тройки, «напиши в
  комментариях / подпишись / твоя очередь», англ. «game changer», «let's dive in», «in a world where»… Хук — конкретный
  факт с числом или названием, биты — цифры, имена, места и даты из трендов, концовка — факт или наблюдение, призыв
  только если о нём попросили. Запрет проверяется кодом (`src/make/slop.ts`, regex-список RU/EN + «хук без числа и
  имени»): найденное отправляется модели на одну переписку (`prompts/make.script.rewrite.md`), остаток — в warnings.
- **Настоящие фото вместо сгенерированных** (`src/make/photos.ts`, по умолчанию `--images photo`). Арт-директор даёт
  к каждому фото-биту 2–4 английских ключевых слова (конкретные существительные, без стилевых слов); поиск в
  Openverse без ключа (как музыка), лицензии только CC0 / Public Domain Mark / CC BY (коммерция разрешена, CC0/PD
  выше в ранжировании), `mature=false`, `size=large`. Отсеиваются скриншоты, графики, логотипы, панорамы, слишком
  маленькие (апскейл > 1.45×) и «цветистые» подписи сгенерированного стока; одно фото не повторяется. Оригинал
  кэшируется в `workspace/_cache/photos/`, ffmpeg режет его под кадр. Нет годного фото — генерация Antigravity
  (если есть agy), иначе типографика. Атрибуция (название, автор, лицензия, ссылка) — в `credits.json`,
  `make.json → photo_credits`, в выводе CLI под хэштегами и в описании, которое присылает бот.
- **Композиция без шаблона** (`src/make/scenes.ts`). Нет постоянной шапки «БРЕНД · 01/07» с прогресс-баром
  (`identity.chrome: "header"` — только если директор решит, для отсчётов); подпись-кикер только там, где она
  несёт информацию (источник, дата), категории вида «ЦЕНЫ · 2026» убираются кодом. Фото-макеты на весь кадр:
  `media_full` (Ken Burns + текст в верхней или нижней трети на скриме), `media_number` (цифра поверх фото),
  `media_split`, плюс `statement` — строка крупно на поле цвета акцента. У каждой сцены `anchor` (top/center/bottom):
  соседние сцены никогда не стоят одинаково; на вертикали «top» у плотных макетов раскладывает заголовок наверх, а
  список/чат/карточки вниз — нижняя треть больше не пустая. Без свечения по умолчанию.
- **Текст идёт за голосом.** С `--voice` каждое слово заголовка появляется в момент, когда диктор его произносит:
  время слов оценивается внутри предложения Piper пропорционально длине произнесённого слова (`speechWords`), слова
  заголовка сопоставляются со словами речи по основам (`alignWords`), остальное интерполируется; пункты списков и
  карточки — тоже по речи. Всё на одной paused-таймлайн GSAP, без CSS-transform на анимируемых узлах.
- **Переходы.** По умолчанию жёсткая склейка на бит (без «вжуха»), иногда whip (рывок с размытием) или zoom-through,
  fade — не больше одного раза; подряд одинаковых движений нет.
- **Живее голос.** Piper для озвучки: `length_scale` 0.92, `noise_scale` 0.72, `noise_w` 0.9 с небольшими
  вариациями темпа ±3% по предложениям (вопросы чуть медленнее), паузы между предложениями 140 мс, хвост сцены 0.35 с.
  `--voice-speed` по-прежнему задаёт базовый темп.
- **16:9 и 1:1.** `--aspect 9:16|16:9|1:1|auto`; auto берёт формат из слов («для ютуба», «youtube», «горизонтальный»,
  «широкоформатный», «16:9» → 16:9; «shorts», «шортс», «рилс», «tiktok», «вертикальный», «9:16» → 9:16 — YouTube
  Shorts вертикальные, «для ютуб шортс» остаётся 9:16; «квадрат» → 1:1), слова формата из темы убираются. Все макеты,
  включая 3D, раскладываются под кадр: в 16:9 две колонки (текст слева, визуал справа), безопасные поля под плеер,
  размеры шрифта от короткой стороны, подгонка текста в Chrome под реальный размер кадра, контактный лист 3 в ряд.
  Бот: `/make 16:9 тема` или «… для ютуба». Монтаж своих видео (`vedit run`, бот): планировщик тоже берёт формат
  из инструкции (правило в `prompts/planner.system.md`, мок — через тот же `detectAspect`).

**Моушн-дизайн и музыка (этап 17).** Сцены больше не стоят на месте:

- **Цифры катятся** как механический счётчик: каждая цифра в `hero_number` / `media_number` — лента 0–9–0–9, которая
  прокручивается до своего значения (правые разряды крутятся дольше), число приземляется с лёгким «ударом»,
  щелчки счётчика в звуке. Приём — как у компонента `number-wheel` реестра HyperFrames (Apache-2.0), реализация своя.
- **Глубина:** за большой цифрой медленно проплывает огромный контурный «призрак» той же цифры; на фото-сценах
  заголовок дрейфует против Ken Burns (параллакс); типографские сцены после входа медленно «наезжают» камерой
  (scale 1 → 1.045), так что удержанный кадр не бывает статичным.
- **Без пустых кадров:** заголовок под голос собирается не позже ≈2 с (или 45% бита), пункты списков/пузыри чата —
  к ~60% бита; раньше слова шли строго за диктором и экран секундами оставался пустым.
- **Музыка слышна:** под голосом подложка теперь −22 LUFS с мягким сайдчейном (ratio 3, атака 10 мс, отпускание
  160 мс): на живом ролике (ebur128 по стемам) музыка −34.7 LUFS при голосе −15.9 LUFS, то есть −18.8 дБ под голосом
  (было −39.5 LUFS, −23.6 дБ — неслышно на телефоне), в паузах между битами она поднимается до −16…−21 LUFS.
  Настроение «dramatic» (нарастающий эпик) под голос заменяется на «upbeat», если тема не просит драмы.
- Всё на одной paused-таймлайн GSAP, без CSS-transform на анимируемых узлах, lint без ошибок.

## Звук и несколько видео → один вирусный ролик (этапы 11–12)

**Звук** (`src/audio/`). Эффекты синтезируются ffmpeg-ом (вжух, поп, щелчок, удар, подъём, звонок, свайп; без
сэмплов и лицензий, кэш `workspace/_cache/sfx`). Музыка по настроению (upbeat, chill, dramatic, inspiring, tech,
funky, emotional): сначала свои треки из `assets/music/` (см. README там), иначе Openverse без ключа — CC0/CC BY
(полные песни Jamendo, лупы Freesound), кэш `workspace/_cache/music`; для CC BY автор и ссылка идут в подпись.
Микшер: музыка петлёй с подъёмом и затуханием, эффекты по меткам, под речью музыка приглушается сайдчейном,
итог −14 LUFS. `make`: настроение выбирает арт-директор, метки эффектов даёт композиция (вжух на смене кадра,
удар на большой цифре, щелчки на пунктах, поп на пузырях чата, свайп на маркере, звонок на призыве);
`--music auto|<настроение>|<файл>|none`, `--no-sfx`. Монтаж: музыка под речью, когда выход EDL просит музыку или
`music_default` пресета (bold_pop — да); `--bg-music`.

**Несколько видео** (`src/ingest/combine.ts`). Видео склеиваются в один источник на общем холсте (ориентация
большинства; вертикальное видео на горизонтальном холсте — целиком на размытом фоне, чтобы кроп 9:16 вернул его
без двойной обрезки), 30 fps, звук 48 кГц (тишина для немых). `sources.json` — карта «v1 0–8 с, v2 8–16 с…»,
она идёт в пак планировщика, и клип не пересекает шов. В Telegram: пришлите несколько видео (по одному или
альбомом) → `/viral` (или задача текстом / подписью к альбому) → один самый вирусный ролик из всех; `/clear` —
новая подборка; после запуска следующее видео начинает новую подборку. Из консоли:
`npx tsx tools/make-viral.ts a.mp4 b.mp4 c.mp4 [-- "задача"]`.

## Сплит-монтаж как у новостных техно-блогеров (`split_news`, этап 13)

Пресет `split_news`: спикер в нижней половине (кадр подбирается по лицу), сверху на каждом смысловом отрезке —
рамка с настоящим фото (и UI-карточками поверх углов: цитата из речи, теги, код, цифра) или моушн-графикой, в
первые секунды на стыке — заголовок-хук в три строки (жирный белый, акцентный, курсив с засечками). Что показать,
решает «режиссёр панелей» (`src/design/panels.ts`, `prompts/split.panels.*`) по транскрипту готового рилса.
Кэш фото/картинок — `design/<id>-panels/`, панели — `design/<id>.panels.json`. Вёрстка — `src/design/hyperframes/split.ts`.
Запуск: `vedit render <job> --design split_news` (или `run … --design split_news`); в Telegram `/style split`
или слова «сплит» / «как у aleko» в задаче.

**Без нейрослопа (этап 17).** Сгенерированные метафоры (молоток судьи, весы, яблоко в воздухе, мозг, лампочка,
шахматы, пазлы, голограммы, «светящиеся узлы»…) больше не попадают в верхнюю половину. Режиссёр панелей выбирает для
каждого отрезка источник (`source` в `design/<id>.panels.json`):

1. **`photo`** (по умолчанию, если в речи названо что-то реальное) — настоящее фото из Openverse тем же поиском, что
   и в `make` (`src/make/photos.ts`: CC0 / Public Domain / CC BY, без 18+, отсев скриншотов и графики). Можно
   искать людей, о которых говорят (публичные фото Wikimedia), места, продукты. Фото кадрируется под рамку панели,
   поверх — Ken Burns с дрейфом и маленькая подпись «фото: автор · лицензия · источник»; атрибуция пишется в
   `design/<id>-panels/credits.json` и добавляется в описание, которое присылает бот.
2. **`graphic`** — моушн-графика кодом (`src/design/panel-graphics.ts`, HTML/CSS + GSAP на общей paused-таймлайн):
   `counter` (цифры катятся как одометр), `bars` и `line` (график рисуется), `quote` (слова выезжают из-под маски),
   `timeline`, `compare` (A vs B), `chat` (вопрос → «печатает…» → ответ ИИ + штамп), `search` (запрос печатается,
   выезжают результаты), `post` (карточка поста без логотипов), `list` (пункты приходят по ходу речи, прошлый
   гаснет). Числа в графиках проверяются кодом: если числа нет в транскрипте, график превращается в цитату.
3. **`ai`** — генерация Antigravity только как последний вариант и только документальный промпт.

У каждой панели всегда есть `graphic` — он показывается, если фото не нашлось или картинка не сгенерировалась.
Фильтр метафор (`bannedMetaphor`) проверяет и промпты, и фото-запросы, в том числе в старых `panels.json` (их панели
становятся графикой). Перерендер одного рилса: удалить `design/<id>.panels.json` и `design/<id>-panels/`, затем
`vedit render <job> --only <id> --design split_news`.

### Вырезание спикера (MediaPipe, этап 21)

В `split_news` спикер вырезается из фона и ставится поверх фирменного фона рилса (цвет `panel_bg`, та же сетка 60 px,
что сверху, акцентное свечение за головой, затемнение к низу под субтитры); голова «выходит» над стыком на
`design.split.pop_out` (в `split_news` 7 % высоты, по умолчанию 6 %; с отступом над макушкой голова выходит над стыком примерно на 4–5 %) и перекрывает низ верхней рамки. Субтитры и хук остаются поверх, на подложке.

- **Режим** — `design.split.cutout`: `off` | `on` | `auto` (в `split_news` — `auto`, в схеме по умолчанию `off`).
  CLI: `vedit render <job> --design split_news --cutout on|off|auto`. `auto` включает вырезание, только если маска
  надёжна (`judgeMatte` в `src/design/matte.ts`: человек занимает 8–92 % кадра, кадров без человека ≤ 15 %,
  медианный IoU соседних масок ≥ 0.85, неуверенных пикселей ≤ 35 %), иначе — обычное видео и предупреждение.
  `on` — вырезает всегда (с предупреждением, если проверка не прошла), а без сайдкара падает с понятной ошибкой.
  Бот работает через пресет (auto); отдельной кнопки в настройках нет.
- **Как** — Python-сайдкар `tools/matte/vedit_matte.py`: ffmpeg отдаёт кадры чернового монтажа (rawvideo, уже
  обрезанные под слой и уменьшенные до ~540 px), MediaPipe Tasks ImageSegmenter (`selfie_segmenter.tflite`, вход
  256×256) размечает человека 15 раз в секунду и на каждом монтажном стыке; маска чистится (тонкие горизонтальные
  полосы — полки, края стола — и мелкие пятна отбрасываются, дыры внутри силуэта заливаются), сглаживается во времени
  (EMA, сброс на склейке), край на каждом кадре подтягивается к настоящей картинке цветным guided filter
  (коэффициенты на ¼ разрешения), слегка «съедается» (без ореола старого фона) и растушёвывается на 2–3 px.
  Второй ffmpeg за один проход склеивает маску с нетронутым видео (`alphamerge`) и пишет два файла:
  **плашку** `*.plate.mp4` — нижняя половина, где спикер уже наложен на фирменный фон (фон рисует сайдкар теми же
  цветами и сеткой, что CSS верхней половины), обычный H.264 — и **полоску** `*.pop.webm` — `pop_out`-строки над
  стыком, **VP9 WebM с альфой** (yuva420p). HyperFrames сам декодирует VP9-альфу (libvpx-vp9 → PNG-кадры), так
  что голова над стыком — второй `<video id="a-pop">` поверх панелей (z-index: фон 0 → панели и линия стыка 1 →
  плашка 2 → полоска 3 → субтитры 4 → хук 5). Почему не один слой с альфой на всю нижнюю половину: так тоже
  работает, но рендер 30-секундного рилса шёл 6–8 минут вместо ~1.5 (PNG 1080×1076 на каждый кадр) и захват
  Chrome дважды зависал на 60 с. Положение: верх головы (25-й перцентиль по пробам раз в секунду) ставится на
  24 px ниже верха полоски; если голова обрезана краем кадра, выхода над стыком нет. Кадры без человека
  (перебивки) показывают обычную картинку в нижней половине.
- **Кэш** — `design/<id>-cutout/cutout_<хэш>.{plate.mp4,pop.webm,json}`; ключ — содержимое `rough_<id>.mp4`,
  параметры (в том числе цвета фона) и текст скрипта.
- **Скорость** (ноутбук, 30 с рилс 1080×1920): маска 21–25 с (≈0.7–0.85× реального времени, 4 потока
  уточнения края).
- **Ограничения**: модель «селфи» — для крупного и среднего плана; волосы получаются мягким краем без отдельных
  прядей; тёмная одежда на тёмном фоне сливается с фирменным фоном; микрофон перед спикером остаётся в кадре, если
  модель считает его частью человека (обычно да — он «перед» спикером), а фон между микрофоном и телом, замкнутый
  силуэтом, заливается; двое в кадре вырезаются оба.

## Внешний GPU для речи (Google Colab T4)

Распознавание 2 ч 17 мин речи на этом ноутбуке заняло 157 минут; на бесплатном Colab с T4 это ~5 минут, а
остальной пайплайн (сцены, Antigravity, план, нарезка, рендер) остаётся локальным. Схема:

```bash
node bin/vedit.mjs ingest video.mp4               # → job
node bin/vedit.mjs asr-export <job>               # → workspace/<job>/asr_upload.ogg (Opus 48 кбит/с, ~20 МБ на час)
# Colab: открыть tools/asr/colab_vedit_asr.ipynb (GPU T4), загрузить asr_upload.ogg и tools/asr/vedit_asr.py,
# выполнить все ячейки → скачается asr_bundle.zip (faster.json, phrases.json, speakers_raw.json)
node bin/vedit.mjs asr-import <job> asr_bundle.zip   # → transcript.json, speakers.json, asr_import.json
node bin/vedit.mjs understand <job> --asr import     # сцены + vision поверх импортированной речи
node bin/vedit.mjs plan <job> -p "…" --speaker most --cut && node bin/vedit.mjs render <job>
```

В Colab работает тот же `vedit_asr.py` (команда `pipeline`: faster-whisper large-v3-turbo float16 на CUDA →
говорящие ECAPA на CUDA → папка бандла). Говорящие размечаются на сырых сегментах whisper; при импорте каждая
фраза после разбиения по предложениям берёт метку сегмента, в который попадает её середина. Ограничения Colab:
бесплатная сессия до ~5 часов, ~12 ГБ RAM, файлы загружаются через браузер (поэтому Opus, а не WAV).

## Аватары (этап 14)

Говорящий аватар бесплатно: текст или тема → речь с клоном голоса → «оживлённое» фото на бесплатном GPU Google Colab
(T4) → обычный монтаж (`split_news`: аватар снизу, сгенерированные картинки и карточки сверху, субтитры, музыка).

```bash
node bin/vedit.mjs avatar export --topic "почему кофе дорожает" [--seconds 40]          # монолог напишет Claude
node bin/vedit.mjs avatar export --text "Привет! Сегодня…" [--photo me.jpg] [--voice me.ogg] [--lang ru]
node bin/vedit.mjs avatar export --speech my_voice.ogg --photo me.jpg                   # своя запись, без синтеза
node bin/vedit.mjs avatar export --text "…" --voice-only                                 # только голос
# → workspace/<job>/avatar_job.zip; Colab: tools/avatar/colab_vedit_avatar.ipynb, T4, Run all, загрузить архив
node bin/vedit.mjs avatar import <job> avatar_result.zip [--design split_news] [-p "1 рилс 30 секунд"]
```

В Telegram: пришлите фото (лицо анфас) и голосовое 5–10 с (по желанию) → `/avatar <текст или тема>` → бот пришлёт
`avatar_job.zip` и инструкцию → после Colab пришлите боту `avatar_result.zip` документом (подпись = задача монтажа)
→ готовый рилс. `/avatar сброс` — забыть фото и голос. Без фото портрет вымышленного ведущего генерирует Antigravity
(`prompts/avatar.portrait.md`: только вымышленные люди, не реальные и не известные).

Как устроено:

- **Бандл** (`src/avatar/export.ts`): `script.json` (язык, строки, настройки голоса и анимации, id задачи), `portrait.png`
  (≤ 1280 px), `voice_ref.wav` (24 кГц моно, ≤ 12 с, тишина в начале срезана) или `speech_in.wav` (своя запись) и сам
  `vedit_avatar.py` — в Colab загружается один файл. Zip пишется и читается на чистом Node (`src/lib/zip.ts`).
  Тема → монолог: structured-вызов Claude по `prompts/avatar.script.*` (разговорные короткие строки, числа словами,
  ≈2.5 слова/с).
- **Colab** (`tools/avatar/colab_vedit_avatar.ipynb` → `tools/avatar/vedit_avatar.py`): речь — **Chatterbox
  Multilingual** (по предложению, паузы 220 мс между предложениями и 450 мс между строками, повтор с другим сидом, если
  длина фразы неправдоподобна); анимация — **JoyVASA** (диффузия мимики и движений головы по звуку, энкодер
  chinese-hubert-base) + рендер **LivePortrait** с вклейкой лица обратно в портрет, 25 fps. Речь длиннее 20 с
  анимируется кусками, которые режутся по паузам между фразами (на стыке голова возвращается в исходную позу — это
  незаметно в паузе и всё равно режется монтажом), куски склеиваются покадрово точно по длине речи. Итог —
  `avatar_result.zip` (`avatar.mp4` H.264 + AAC, `speech.wav`, `meta.json` с таймингами строк, версиями и временем);
  архив ужимается до 19 МБ, чтобы пройти через бота.
- **Окружения в Colab**: два изолированных venv через `uv` на Python 3.11 — Chatterbox требует `transformers 5.2`,
  JoyVASA — `4.39` (его HuBERT-энкодер наследует внутренние классы transformers). В обоих `torch 2.6.0` (cu124),
  `uv` скачивает его один раз; ядро Colab и его torch не трогаются, перезапуск runtime не нужен, ячейки перезапускаемы
  (готовые этапы пропускаются по хэшу входа). JoyVASA закреплён на коммите, веса качаются `snapshot_download` только
  нужные (без animal-режима и XPose).
- **Импорт** (`src/avatar/import.ts`): проверка `meta.json`, ffprobe (есть видео и звук, длина = длине речи ±3 %,
  `speech.wav` той же длины, кадр ≥ 256 px) → `avatar.mp4` становится исходником той же задачи → ingest → understand →
  plan → cut → render. Речь всё равно распознаётся whisper: один путь кода и настоящие пословные тайминги для
  подсветки субтитров (синтезированная речь чистая, whisper на ней точен); сценарий только сверяет транскрипт
  (`сверка со сценарием: N/M слов`, предупреждение ниже 60 %).
- **Проверка без GPU**: `python tools/avatar/vedit_avatar.py selftest` — синтетическая речь и видео через ffmpeg
  (нарезка по паузам, склейка, сведение, zip, пропуск готовых этапов); `tests/stage14-avatar.test.ts`.
  Локальный CPU-прогон (`tools/avatar/.venv/{tts,joy}`, веса в `tools/avatar/.cache/`): на Windows JoyVASA должен лежать
  по пути без кириллицы (OpenCV), на CPU работает только для проверки (минуты на секунды видео).

Лицензии: Chatterbox — MIT, в синтезированной речи неслышимый водяной знак Perth (Resemble AI); JoyVASA, LivePortrait,
chinese-hubert-base — MIT. ⚠️ **InsightFace buffalo_l** (детекция лица внутри LivePortrait) — **только некоммерческое
исследование**: для тестов можно, **TODO до коммерческого запуска — заменить на MediaPipe Face Detection** (Apache-2.0).
Стоимость: $0 (Colab бесплатно; Claude — только для монолога по теме, ≈$0.03). Языки синтеза — 23 языка Chatterbox
(ru, en, tr, de, …; узбекского нет — для него `--speech` со своей записью).

- **Ключи.** `GEMINI_API_KEY` (aistudio.google.com → Get API key) — Gemini API; `GOOGLE_CLOUD_API_KEY` (Cloud Console →
  APIs & Services → включить «Cloud Text-to-Speech API» → Credentials → Create API key, ограничить этим API) —
  Cloud TTS. Если есть оба, gemini_* идут через Cloud Gemini-TTS (`gemini-2.5-flash-tts`, стиль — поле `prompt`),
  chirp_* — через Chirp 3: HD; без Cloud-ключа chirp_* говорят тем же голосом через Gemini API (с предупреждением);
  без ключей все облачные голоса заменяются своим Piper-голосом, а CLI/бот пишут по-русски, где взять ключ.
- **Gemini API** (`src/voice/gemini.ts`, доки проверены 15.10.2026): модели `gemini-3.8-flash-tts` →
  `gemini-3.1-flash-tts-preview` → `gemini-3.8-flash-lite-tts` → `gemini-2.5-flash-preview-tts` (с этапа 25 lite раньше
  2.5: на одной озвучке lite сказал все бренды верно, 2.5 — «Клоуд», «Энтропик»; `VEDIT_GEMINI_TTS_MODEL` — первой).
  **Бесплатный уровень: 10 запросов в сутки на модель** (3.8, проверено 18.10.2026) — поэтому озвучка идёт одним дублем. Запрос — Interactions API (`/v1beta/interactions`, стиль в
  `speech_metadata.style`), запасной — `generateContent` (`responseModalities: ["AUDIO"]`, `prebuiltVoiceConfig`).
  Проверено живьём: 3.8 в `generateContent` **читает вслух** префикс-инструкцию «Say as …», поэтому стиль там
  добавляется только для 2.5-моделей. Ответ — WAV (RIFF) или сырой PCM 24 кГц s16le — разбираются оба.
  Ключ — в заголовке `x-goog-api-key`, не в URL. 429 → пауза по RetryInfo/Retry-After (экспонента, до 40 с, 4 повтора),
  дневная квота → следующая модель, 404 → следующая модель; 1 запрос за раз (`VEDIT_GEMINI_TTS_CONCURRENCY` до 2).
- **Как озвучивается ролик.** Один стиль на всю озвучку (`NARRATOR_STYLE`; с этапа 25 — быстрый «новостной
  объясняющий» диктор, `VEDIT_GEMINI_TTS_STYLE=doc` возвращает документального), с этапа 25 — **весь текст одним
  запросом** (абзац на бит, дубль режется на биты по словам (маленький whisper), запасной путь — по паузам, затем запрос на бит, `VEDIT_TTS_TAKE=line`),
  текст перед синтезом проходит слой произношения (бренды, числа с падежами — см. «Этап 25»), тайминги строк — точные
  по сэмплам, предложений — пропорционально длине. Результат того же вида, что у Piper, поэтому make, слова-за-голосом и
  `avatar export` работают без изменений (аватар с Gemini-голосом: речь делается здесь, Colab только анимирует).
  Кэш: `workspace/_cache/tts/{gemini,cloud}/` по хэшу текст+голос+стиль+модель.
- **Цена.** Бесплатный уровень Gemini API — $0 (но Google может использовать запросы; для продакшена — платный:
  ≈ $9 за 1 млн аудио-токенов ≈ $0.02 за минуту речи). Cloud Gemini-TTS — бесплатной квоты нет (≈ $0.015/мин),

Как устроено (`src/voice/`):

- **Piper** (MIT, релиз 2023.11.14-2) — отдельный бинарник; ставится сам при первом синтезе в `tools/voice/bin/`
  (~22 МБ), голоса — в `tools/voice/models/` (~60 МБ каждый, скачиваются при первом использовании с проверкой размера).
  Обе папки в `.gitignore`. Как и whisper.cpp, piper/espeak-ng не открывают файлы по пути с кириллицей — процесс
  запускается из своей папки с относительными путями, звук забирается из stdout (`--output_raw`). Скорость на
  i7-13700 ≈ 0.1× реального времени (10 с речи ≈ 1 с).
- **Нормализация текста** (`normalize.ts`, чистые функции с тестами): числа словами с согласованием
  («30%» → «тридцать процентов», «21 тысяча», «1,5%» → «полтора процента»), годы после «в/к» («в 2026» →
  «в две тысячи двадцать шестом году»), `$`/`₽`/`€`, «млн/млрд/тыс», «×3» → «в три раза», т.е./т.д./ИИ;
  эмодзи, хэштеги и markdown вырезаются. С этапа 25 падеж числа берётся из предлога перед ним («от 400 млн до 4,6 млрд»
  → «от четырёхсот миллионов до четырёх и шести десятых миллиарда»), плюс диапазоны, кварталы, «2024-го», даты, время.
- **Синтез** идёт по предложениям (до 3 процессов параллельно), куски склеиваются с паузами (180 мс внутри строки,
  380 мс между строками), тайминги каждой строки и предложения — точные, по числу сэмплов.
- **make --voice**: сценарист теперь пишет к каждому биту `voiceover` — 1–2 разговорные фразы (не копия текста на
  экране); без него читается текст бита. Каждый бит растягивается под свою речь (0.25 с до + речь + 0.45 с после,
  по сетке кадров, 2–15 с), речь кладётся на таймлайн с началом каждой сцены (`make/voice/voice.wav`,
  `voice.json`). Сведение: голос отдельно выравнивается до −16 LUFS, музыка (−27 LUFS) и эффекты (−5 дБ)
  приглушаются side-chain-компрессором по голосу, итог −14 LUFS. `--voice-captions` — короткие субтитры речи поверх
  сцен (по умолчанию выключены: текст и так на экране). По умолчанию голоса нет — как раньше.
- **avatar export --voice**: для Piper-голоса речь синтезируется локально в `speech_in.wav` (24 кГц) вместе с
  таймингами строк (`script.json → speech_meta`); ноутбук в этом случае **не ставит Chatterbox вовсе** (ни venv, ни
  веса ~3 ГБ) и только анимирует лицо. Для `chatterbox_denis/dmitri` Piper читает нейтральный абзац ≈ 9 с → он идёт
  как `voice_ref.wav`, и Chatterbox говорит этим тембром. Свой файл `--voice мой.ogg` или `--speech запись.ogg`
  важнее голоса из каталога. `--voice` по-прежнему принимает и путь к файлу-образцу.

## Хайлайты спорта и экшена (`--mode highlights`, этап 18)

Видео без речевого сюжета — игра, тренировка, трюки — монтируется не по транскрипту, а по событиям:

```bash
node bin/vedit.mjs run game.mp4 -p "нарезка лучших моментов баскетбола, музыка, акценты на бросках"          # режим определяется сам
node bin/vedit.mjs run game.mp4 -p "…" --mode highlights [--target 50] [--no-editor] [--bg-music sport|файл] [--workers 1]
node bin/vedit.mjs highlights <job_id> [-p "…"] [--no-render]     # перепланировать задачу (ответы Gemini из кэша — бесплатно)
node bin/vedit.mjs understand <job_id> --events                    # только события → events.json
```

**Когда включается.** `--mode auto` (по умолчанию): слова о спорте или игровых действиях («баскет», «футбол», «броски»,
«трюки», «как мы играем в…») — сразу highlights; общие слова («хайлайты», «лучшие моменты», «нарезка») — только если в
видео мало речи (4 пробы whisper по 15 с: речь < 25 % звука), иначе обычный монтаж по речи (подкаст остаётся подкастом).
Бот делает то же с подписью к видео (`src/bot/index.ts` → `runHighlightsBot`; для «слабых» слов решает по готовому
транскрипту). Бот скачивает через облачный Bot API только файлы до 20 МБ — часовое видео идёт через CLI или локальный
`telegram-bot-api` (`TELEGRAM_API_BASE`, до 2 ГБ).

**Как устроено** (`src/understand/{events,gemini-client,refine,scan}.ts`, `src/highlights/`, `src/audio/beats.ts`):

1. *Лёгкий ingest* (`ingestLight`) — часовой файл не перекодируется в 30 fps: нарезка читает оригинал, и только из
   60 fps получается гладкое замедление 0.5× (каждый кадр уникален).
2. *События (Gemini)* — исходник режется на чанки ~8 мин, каждый перекодируется в 480p/10 fps с моно-звуком 16 кГц,
   один раз загружается через Files API и спрашивается дважды: основной проход (`video_metadata.fps = 2`,
   `media_resolution: low`, ≈100 токенов/с) — броски, ключевой момент, дальность, где кольцо; проход «люди»
   (`prompts/events.social.user.md`, 0.5 кадра/с, важен звук) — кто подошёл, о чём просят, реакции. Ответ — JSON по схеме,
   MM:SS переводятся во время исходника, дубли на стыках чанков сливаются. Раз в 8 минут кадр в полном разрешении даёт
   рамку кольца с сеткой (камера могла сдвинуться — на тестовом видео сдвинулась на 40-й минуте). Модели по порядку
   `gemini-3.8-flash → 3.6 → 3.7 → 3.5 → flash-latest` (`VEDIT_EVENTS_MODEL`): 429 ждёт `retryDelay`, перегрузка (503) —
   два повтора и следующая модель, дневная квота бесплатного уровня (20 запросов в день на модель) — модель пропускается
   до конца прогона; если заняты все — ещё до трёх кругов с паузой 90 с (проход «люди» без пауз: он необязательный).
   Кэш ответов — `workspace/_cache/events/` по хэшу (файл, диапазон, промпт, настройки): новая задача на том же видео
   ничего не стоит, недостающие чанки прохода «люди» доспрашиваются при следующем запуске.
3. *Проверка бросков по кадрам* (`refine.ts`, без модели) — модель на 480p путает попадания с промахами (на тестовом
   видео большинство настоящих попаданий она назвала промахами и наоборот), поэтому решает локальный трек: 3 с вокруг
   броска в окне у кольца при 60 кадрах/с; фон — медиана окна, мяч — коричневые пятна размером с полкольца (белая сетка
   и синий щит не проходят по цвету, человек — по размеру); мяч сверху в кольцо → в сетку (или мяч в «ядре» сетки,
   пустом до этого) = попадание, отскок вверх/вбок = промах. Камера смотрит снизу, поэтому мяч, упавший перед кольцом,
   тоже пересекает сетку в кадре: попадание засчитывается, только если после мяча качнулась сетка (доля изменившихся
   пикселей сетки ≥ 0.17; если мяч сначала лежал на дужке — нижняя половина сетки ≥ 0.18). Момент «мяч у кольца» точен
   до кадра (1/60 с), рядом ищется онсет звука (удар о дужку/щит, high-pass 1.2 кГц).
4. *Скан всего видео* (`scan.ts`) — окно у кольца декодируется целиком при 30 кадрах/с (≈4 мин на час видео, ~200 МБ
   памяти), каждый подлёт мяча к кольцу классифицируется так же; попадания, которых модель не записала, проверяются при
   60 кадрах/с и добавляются как события `sNNNN`.
5. *Отбор* (`src/highlights/plan.ts`) — правила: попадания по очкам (уверенность трека, дальность, «чисто», серия;
   мяч, лежавший на дужке, — в последнюю очередь), равномерно по всей игре (каждое уже взятое попадание из того же
   8-минутного окна снижает очки следующего), 1–2 момента с людьми, промахи — максимум два и только если попаданий не
   хватает до цели (45–60 с, `--target`, «на минуту» в инструкции); лучший бросок открывает ролик, остальное по
   хронологии; повтор лучшего броска. Затем, если есть вход Claude, один structured-вызов «редактора»
   (`prompts/highlights.*`): титр-хук (1–3 слова, без клише и эмодзи), какой бросок первым, что выкинуть (ролик
   дополняется следующими по очкам), до 3 плашек («x3», «ЧИСТЫЙ», «С ДАЛЬНЕЙ»), строка под каждым моментом с людьми.
6. *Монтаж броска* — три клипа из 60 fps оригинала: разбег 1× с медленным наездом 1→1.15× → полёт и сетка 0.5× с
   наездом на кольцо до 1.9× (ease-out 0.45 с; `scale eval=frame` + `crop`, lanczos, unsharp) и вспышкой в момент
   «мяч в сетке» (тряска — на открывающем броске и повторе) → реакция 1× с отъездом. Повтор — ещё раз 0.5× крупнее.
   Звук: вжух на входе в замедление, «свиш» сетки (синтез ffmpeg), удар на открывающем броске; живой звук площадки
   тихо (0.6, в замедлении — 0), у людей — полностью.
7. *Музыка по битам* — трек настроения `sport` (свои треки из `assets/music/` или Openverse CC0/CC BY; «chill/lofi/calm»
   отсеиваются, трек должен быть не короче ролика — петля сломала бы сетку), сетка битов (онсеты → автокорреляция
   70–190 BPM, гребёнка выше 140 считается восьмыми и делится на два → фаза), старт трека на бите после вступления;
   разбег каждого броска удлиняется/укорачивается до ±0.3 с, чтобы «мяч в сетке» попал в бит, а хвост — до ±0.15 с,
   чтобы склейка была на бите. Музыка −15 LUFS, площадка −2 дБ, на людях музыка приседает на 10 дБ (автоматизация
   громкости, не сайдчейн — иначе она «качалась» бы от каждого удара мяча), итог — линейная подстройка до −14 LUFS,
   true peak ≤ −1.5 dBFS.
8. *Оформление* — пресет `sport_highlights`: титр-хук на первом броске, плашки-акценты (`style: "callout"`, жёлтая
   метка над кольцом), субтитры только на репликах людей (whisper только по этим клипам; узбекская речь, принятая за
   турецкую, распознаётся заново как `uz`; зацикленный или односложный текст — галлюцинация уличного шума — отбрасывается,
   и тогда под клипом идёт строка редактора, `style: "lower"`), без аутро.

### Отдельный ролик на каждого игрока (`--per-person`)

```bash
node bin/vedit.mjs highlights <job_id> --per-person [--workers 1]     # или слова «по отдельности», «на каждого игрока» в инструкции / подписи боту
```

Один ролик 60–90 с на каждого, кто бросал (≥ 3 бросков): приход (живой звук + строка редактора), все его попадания по
порядку (мало попаданий — мячи, дошедшие до дужки, и его собственные моменты с людьми, найденные по одежде в описаниях),
лучшее попадание последним с повтором, длинная реакция в конце. Титр — нейтральное описание по одежде от редактора
(«ИГРОК В БЕЛОЙ ФУТБОЛКЕ»), имена не выдумываются. Выходы `reel_p1 … reel_pN` в одной задаче, бот присылает все.

Кто бросал (`src/highlights/people.ts`, `persons.json`, `players.json`, лист `persons.jpg`):
1. *Проход «игроки»* (Gemini, по чанку на запрос, та же загрузка 480p): состав с описанием одежды, переносится из чанка в
   чанк (id не меняются), и для каждого броска из списка (время «мяч у кольца») — кто бросал. «Присоединился» для уже
   известного человека не считается приходом.
2. *Мяч назад к рукам* (`findShooter`): весь кадр в половинном размере, 30 кадров/с, мяч ведётся от кольца назад до
   человека, который его бросил, — рамка бросавшего на листе. На тестовой игре так нашёлся бросавший у 71 из 262 бросков:
   часто игроки бросают от камеры и в момент броска они за краем кадра.
3. *Цвет одежды* бросавшего (верх/низ) считается и показывается, но броски по нему не переносятся (`colorMoves`, выкл.):
   тёмные футболки в тени различаются плохо, автоматический перенос ошибался так же часто, как помогал.
4. *Повторный вопрос по каждому попаданию* (вырезки M1…M56 одним видео, `makesPass`, выкл.): на тестовой игре модель
   отдала 47 из 56 попаданий «чёрной футболке» с уверенностью 1 и ошиблась на большинстве проверяемых глазом; проход по
   чанкам был прав в 11 из 13 таких случаев — поэтому решает он.
5. *Проверка глазом*: лист `persons.jpg` (кадр в момент броска, красная рамка — найдено по мячу, синяя — догадка модели),
   ошибки правятся в `players.fix.json` (`shots`: бросок → человек, `merge`: слить двух, `looks`: описание) — правки
   применяются поверх автоматики при каждом планировании.

Результаты в задаче: `events.json` (все события, рамки кольца, вердикты трека, токены), `highlights.json` (что попало в
ролик, где на шкале, какие броски на бите, музыка, BPM, редактор), `edl.json` (обычный EDL: `speed`, `zoom`, `flash`,
`shake`, `volume`, `hfr` у клипов; `sfx`, `audio` у выхода — тот же cut/render).

Измерено на 54:40 баскетбола (720×1280, 59.94 fps, штатив): Gemini — 17 удачных ответов (7 чанков основного прохода,
3 из 7 чанков «люди», 7 кадров кольца), ≈610k входных / 65k выходных токенов, бесплатный уровень ($0); из-за 503/429 и
исчерпанной дневной квоты основной модели детекция заняла ~40 мин ожидания. Проверка 248 бросков + скан ≈4–5 мин
(347 подлётов к кольцу, 56 подтверждённых попаданий, 14 из них модель не записала); план + нарезка ≈1.5 мин; рендер
56 с ролика — 5.3 мин на 1 воркере. Итог: 9 попаданий + 2 момента с людьми, 56 с, −14.1 LUFS.

## Пользователи, кнопки, лимиты (этап 19)

Бот стал продуктом для многих пользователей: регистрация, меню и кнопки на трёх языках, личные настройки, дневные
лимиты и кредиты, общая очередь задач с отменой, админка, автоочистка файлов. Все старые команды работают как
сокращения (`/make`, `/viral`, `/revise`, `/style`, `/voice`, `/send`, `/avatar`, `/clear`, `/status`, `/cancel`).

```bash
# .env
TELEGRAM_BOT_TOKEN=…
TELEGRAM_ADMIN_IDS=111111111            # админы (/admin, технические ошибки задач); по умолчанию — первый id из ALLOWED
# TELEGRAM_ALLOWED_USERS=111,222        # задан → закрытая бета (остальных бот молча игнорирует); пусто → открытая регистрация
# VEDIT_MAX_JOBS=1                      # задач одновременно: по умолчанию 1 при < 12 ГБ RAM или VEDIT_SERVER=1, иначе 2
# VEDIT_RETENTION_DAYS=7                # загрузки и готовые задачи старше — удаляются раз в сутки
npm run bot
npx tsx tools/bot-smoke.ts              # прогон сценариев на поддельном Bot API (без Telegram, второй экземпляр не мешает живому)
```

**Регистрация** (`/start` нового пользователя): язык (🇷🇺 Русский · 🇺🇿 O‘zbekcha · 🇬🇧 English) → короткое интро и
цель (Блог/контент · Бизнес/реклама · Спорт · Другое) → условия и конфиденциальность (кнопки 📄/🔒 присылают полные
тексты из `docs/legal/{terms,privacy}.{ru,uz,en}.md` — **черновики для юриста**) → ✅ Принимаю → пробные кредиты и
главное меню. Повторный `/start` показывает меню. Админы из `TELEGRAM_ADMIN_IDS` регистрацию не проходят. Все строки —
`src/bot/i18n.ts` (ru/uz/en; узбекский — латиница; пропущенный ключ — ошибка компиляции и теста).

**Меню** — постоянная клавиатура под полем ввода (на телефоне всегда видна): 🎬 Монтаж из моих видео · 🎯 Монтаж как в примере (этап 22) · ✨ Ролик по теме ·
🏀 Хайлайты игры · 🧑 Аватар · ⚙️ Настройки · 💳 Баланс · ❓ Помощь. Сценарии спрашивают только нужное, свободный текст
по-прежнему принимается:

- **Монтаж**: «пришлите видео» → после загрузки (одного, нескольких или альбома) карточка с кнопками: что сделать
  (Рилсы из лучших моментов / Один вирусный ролик / Хайлайты / По отдельности на каждого), сколько (1/3/5), длина
  (30/60/90 с), формат (9:16/16:9), стиль (Динамичный/Сплит/Спокойный) и «▶️ Начать». Выбор отмечается ✓ правкой той же
  карточки; кнопки собирают инструкцию для планировщика (`draftInstruction`). Свой текст вместо кнопок — как раньше.
- **Ролик по теме**: тема → карточка формата и голоса (Авто, Без голоса, голоса Gemini и Piper; ▶️ рядом — проба) → старт.
- **Настройки**: формат, стиль, как присылать (файл/видео/оба), голос (список с пробами), язык (меню переключается),
  новости бота (отписка от рассылок).
- **Прогресс**: одна карточка, которая правится на месте (не чаще раза в 1.5 с): `⏳ в очереди: N` → `▓▓▓░░░░░░░ 25% ·
  понимаю видео` → план → нарезка → `рендер 50%` (по процентам HyperFrames) → звук → `✅ готово · ⏱ 3:12`; кнопка
  🛑 Отменить. Русскоязычным видна и строка пайплайна (сводка плана и т. п.).
- **Результат**: 🔁 Ещё вариант · ✏️ Поправить (текст → обычный `revise`; для ролика по теме — новый сценарий с правкой) ·
  📐 Другой формат (9:16 ↔ 16:9: монтаж — через `revise`, ролик по теме — тот же сценарий, `make --from`) · оценка 1–5 ⭐.
- **Ошибка**: пользователь получает понятный текст и «🔁 Попробовать ещё раз», админы — техническую ошибку с id задачи.
  Технические предупреждения и пути на сервере видят только админы.

**Отмена по-настоящему.** Каждая задача идёт в `AsyncLocalStorage` со своим `AbortSignal` (`src/lib/abort.ts`); все
места, где запускаются процессы (ffmpeg/ffprobe, whisper-сайдкар, скан мяча, agy, Piper, HyperFrames), передают его в
`spawn`, а бюджет планировщика добавляет его к своему сигналу (Agent SDK / API). 🛑 убивает текущий дочерний процесс сразу,
а не «после шага»; задача, которая не остановилась за 60 с, всё равно освобождает слот очереди. В CLI сигнала нет — поведение
прежнее.

**Очередь** (`src/bot/queue.ts`): одновременно `VEDIT_MAX_JOBS` задач, у пользователя максимум 1 в работе и 2 в очереди
(третья — «дождитесь или /cancel»). Честный порядок: сначала по одной задаче каждого пользователя (кто давно не получал
слот — раньше), потом вторые — человек с пачкой задач не задерживает остальных. Задачи хранятся в базе: после перезапуска
ожидающие снова встают в очередь (их карточки продолжают обновляться), прерванные помечаются ошибкой, лимит за них
возвращается, пользователь получает «Попробовать ещё раз».

**Лимиты и кредиты** (`src/bot/plans.ts`, в реестре `vedit modules` → `users.*`): бесплатно в сутки 3 обычные задачи
(монтаж, ролик по теме, правка, монтаж аватара) и 1 длинная (видео длиннее 15 мин или хайлайты); сверх — кредиты (обычная
1, длинная 3), пробных при регистрации 3. Задание для аватара (zip для Colab) бесплатно. Сутки — по `VEDIT_TZ_OFFSET`
(по умолчанию UTC+5). Неудачные и отменённые задачи лимит не тратят, списанные кредиты возвращаются. 💳 Баланс
показывает остаток; оплаты пока нет («скоро: оплата»), кредиты начисляет админ. Размер загрузки на бесплатном тарифе
`VEDIT_FREE_UPLOAD_MB` (не больше лимита Bot API: 20 МБ облако, 2000 МБ с `TELEGRAM_API_BASE` локального сервера).
Расходы на модели каждой задачи берутся из её `cost.json` и копятся в `usage`.

| переменная | по умолчанию | что |
|---|---|---|
| `VEDIT_FREE_JOBS_PER_DAY` | 3 | бесплатных обычных задач в день |
| `VEDIT_FREE_LONG_PER_DAY` | 1 | бесплатных длинных задач в день |
| `VEDIT_TRIAL_CREDITS` | 3 | кредитов после регистрации |
| `VEDIT_CREDITS_STANDARD` / `VEDIT_CREDITS_LONG` | 1 / 3 | цена задачи сверх лимита |
| `VEDIT_LONG_MINUTES` | 15 | видео длиннее — длинная задача |
| `VEDIT_FREE_UPLOAD_MB` | 20 | максимум файла от пользователя |
| `VEDIT_MAX_JOBS` | 1 (< 12 ГБ RAM) / 2 | задач одновременно |
| `VEDIT_RETENTION_DAYS` | 7 | хранение загрузок и готовых задач |
| `VEDIT_TZ_OFFSET` | 5 | граница суток для лимитов, часы от UTC |

Админ меняет числа бесплатного тарифа на лету (`/admin → ⚙️ Лимиты`, хранится в базе и сильнее переменных).

## Сервер: только ключи API (этап 20)

Бот работает на сервере сам, без входов разработчика. `VEDIT_SERVER=1` (или авто: нет `agy` в PATH и нет входа
Claude Code) — провайдеры не трогают Antigravity и подписку Claude:

| что | локально (ноутбук) | сервер (`VEDIT_SERVER=1`) |
|---|---|---|
| LLM (план, сценарий, перевод) | Claude: ключ API, иначе вход Claude Code; иначе Gemini | `ANTHROPIC_API_KEY`, иначе **Gemini** (`GEMINI_API_KEY`, этап 29) |
| тренды для `make` | Antigravity (поиск в вебе) | Gemini + Google Search grounding (`src/make/trends-gemini.ts`; источники фактов — из цитат) |
| ИИ-картинки (запаска к фото) | Antigravity | Gemini image API (`src/make/images-gemini.ts`, `VEDIT_IMAGE_MODEL`); нет квоты/бесплатного уровня → только фото и типографика |
| понимание кадра | Gemini API, иначе agy | Gemini API |
| задач одновременно | 1 при < 12 ГБ, иначе 2 | 1 (`VEDIT_MAX_JOBS`) |

Поиск Google в Gemini и генерация картинок **не входят в бесплатный уровень** Gemini API: с бесплатным ключом тренды
пропускаются (`make` пишет сценарий без них), картинки — нет, остаются фото Openverse.

```bash
vedit doctor [--bot] [--json]   # режим, бэкенд каждого модуля, недостающие бинарники/ключи; код 1 — нет обязательного
# лимиты против расходов (бот, админы не ограничены):
# VEDIT_USER_DAILY_JOBS=10      # задач на пользователя в день, жёсткий потолок (кредиты не помогают); 0 = нет
# VEDIT_BUDGET_DAILY_USD=10     # общий расход API за сутки (cost.json всех задач бота, и упавших тоже); выше — новые задачи ждут завтра
```

Linux / ARM64: Chrome — `VEDIT_CHROME` / `HYPERFRAMES_BROWSER_PATH` (+ поиск в кэшах puppeteer, HyperFrames, Playwright и

## Монтаж по примеру (этап 22)

Пользователь присылает **рилс-пример** (файлом; ссылкой — если есть yt-dlp) и своё сырое видео — бот монтирует его в стиле
примера: темп и ритм склеек, вырезанные паузы (джамп-каты), субтитры (размер, цвета, позиция, анимация слова), наезды
камерой, музыка, звуки на склейках, цвет. Сам пример в ролик не попадает.

```bash
vedit style ref.mp4 [--json] [--out dna.json] [--force]          # Style DNA примера + как она ляжет на наши настройки
vedit style "https://www.instagram.com/reel/…"                     # ссылка: нужен yt-dlp (PATH или VEDIT_YTDLP)
vedit run raw1.mp4 raw2.mp4 --like ref.mp4 -p "1 рилс 30 секунд"   # несколько видео склеиваются; без -p — 1 рилс 30–45 с
```

Бот: главное меню → **🎯 Монтаж как в примере** (`H:ref`) → «пришлите пример (файлом или ссылкой)» → короткая сводка
(«Быстрый темп, склейка каждые 1.5 с, паузы вырезаны (джамп-каты), субтитры по 2 слова капсом, активное слово бирюзовым,
наезды на каждой склейке…», ru/uz/en) → «теперь пришлите своё видео» → обычная карточка (сколько / длина / формат), вместо
кнопок стиля — переключатель **«🎯 Как в примере ✓»** → ▶️. Пример со сплит-экраном (`split_screen_detected`) идёт на
пресете `split_news`. Анализ примера входит в задачу (отдельно не списывается; его стоимость Gemini пишется в `cost.json`
первой задачи с этим примером); повтор того же файла, пересланного файла (`file_unique_id`) или ссылки — из кэша, $0.
Пример держится до `/clear` или до «🎬 Монтаж из моих видео».

**Style DNA** (`src/style/dna.ts`, zod → Gemini `responseSchema` с enum'ами, которые модель обязана соблюдать при
декодировании; после разбора все числа зажимаются в безопасные диапазоны, сломанное поле → значение по умолчанию):
`style_summary` · `planner_rules` (темп, длина склейки в хуке и в теле, порог пауз, паразиты/дубли, слов в минуту) ·
`hyperframes_theme` (субтитры, движение камеры, оверлеи) · `audio_and_color` (музыка, приглушение, эффекты, цвет).

**Маппинг** (`src/style/map.ts`, чистая функция; задача хранит только DNA в `workspace/<job>/style.json`, каждый этап
выводит из неё своё):

| поле DNA | наша переменная |
|---|---|
| `pacing_profile` | `preset.pace` (calm → calm, moderate → neutral, fast/aggressive → dynamic) + блок правил планировщика; при fast/aggressive режутся и длинные куски |
| `hook_cut_duration_sec`, `body_avg_cut_duration_sec` | правила планировщика (ритм хука и тела), `preset.clip_seconds` = 0.5–2.2 × длина склейки; `cleanup.maxPiece` = 1.6 × длина склейки (длинный кусок режется по паузе между словами, крупность меняется) |

| `remove_fillers_and_retakes` | чистка (э, ммм, uh, um — всегда; ну, короче, типа, как бы, like… — только между паузами) + правило планировщику убирать дубли |

| `uppercase`, `position_y_percent` | `design.captions.uppercase`, `anchor_y = %/100` |

| `secondary_accent_color` | `design.split.accent` |
| `stroke_width_px`, `shadow_opacity` | `design.captions.stroke_width`, `shadow_opacity` (новое поле — тень букв) |

Наш хаус-стиль, которого нет в примере, выключается: затемнение под субтитрами, CTA-аутро «Подпишись».

**Что меряется, а что угадывается** (`src/style/metrics.ts`, `src/style/extract.ts`, без новых зависимостей):

- *Меряется локально* и **побеждает модель**: склейки → длина плана в хуке и в теле → темп; слова в минуту, паузы
  между словами (p90 × 1.15 → порог пауз, 150–600 мс), найденные паразиты (≥ 2 → пример их не вырезает); громкость пауз
  между словами против речи (музыка); `signalstats` (яркость, контраст, насыщенность — как подсказка модели).
- *Склейки*: детектор сцен ffmpeg (`select='gt(scene,0.18)',showinfo`) ловит жёсткие склейки, но **не видит джамп-каты
  внутри одного плана** (на наших рилсах «говорящая голова» — 0 из 4–5 склеек). Поэтому второй детектор: крошечные серые
  кадры 72×128 при 30 к/с, разница соседних кадров в трёх горизонтальных полосах; склейка — одиночный импульс (≥ 2×
  соседних кадров, ≥ 3× локальной медианы) сразу в ≥ 2 полосах: смена страницы субтитров зажигает одну полосу, поворот
  головы нарастает несколько кадров. На 4 рилсах задачи `20261012-dd70df` найдены все 16 склеек EDL (ещё 2 срабатывания
  в одном рилсе там же, где их видит и детектор сцен ffmpeg, — вероятно, смена плана в самом исходнике), на примере ниже — 15 из 15. PySceneDetect (BSD-3) сравнивает кадры так же (HSV), джамп-каты он не видит точно так же, а на
  ARM-сервере потянул бы Python + OpenCV — поэтому сайдкар не добавлен.
- *Угадывает Gemini* (видео ≤ 90 с, ≤ 960 px, со звуком, 4 кадра/с, `media_resolution: high` — на low модель путала цвет
  обычных и активных слов и не видела тонкую полосу прогресса): типографика, цвета, анимация, наезды, сплит, оверлеи,
  музыка, эффекты, цвет. Промпт — `prompts/style.dna.{system,user}.md`, замеры идут в него как точные данные,
  `temperature 0.1`, файл удаляется из Files API в `finally`. Модели `gemini-3.8-flash → 3.6 → 3.7 → 3.5 → flash-latest →
  3-flash-preview → 2.5-flash` (`VEDIT_STYLE_MODEL`), 429/503 — общий `GeminiClient`. Без ключа — ритм по замерам,
  визуальное по умолчанию (с предупреждением).

**Чистка (джамп-каты)** — `src/style/jumpcut.ts`, детерминированно по пословным таймкодам, после плана: каждый клип
планировщика режется на паузах длиннее порога, паразиты выкидываются, у каждого куска ручка ≤ 40 мс, которая никогда не
заходит в соседнее слово (края всегда вне слов), куски ближе 80 мс склеиваются обратно, клип без слов (перебивка) не
трогается. Повторная чистка ничего не меняет (правка `revise` оставляет нетронутые выходы прежними). Валидатор считает
длительность **после** чистки (ошибка «слишком коротко» говорит модели, сколько вырезано) и в режиме примера сдвигает клип,
начатый на слове, которым закончился предыдущий (иначе слово звучит дважды). Планировщик получает блок правил на русском
(`{{style}}` в `prompts/planner.task.md`) и поле `punch_in` у клипа для наездов на акцентах.

**Кэш** (`src/style/cache.ts`): ключ — sha256(размер ‖ первые 512 КБ ‖ последние 512 КБ); профиль —
`workspace/_cache/style/<ключ>.json`, алиасы (`aliases.json`): `tg:<file_unique_id>`, `url:instagram:reel:<код>`,
`url:tiktok:<id>` (`tiktok:short:<код>` для vm./vt.), `url:youtube:shorts:<id>` / `url:youtube:<id>`, иначе хост + путь без
трекинга (utm_*, igsh, si, feature…). В боте ещё таблица `style_cache` (миграция 2): алиас → ключ, чтобы пересланный пример
не скачивался. **Ссылки**: yt-dlp (Unlicense, по желанию); Instagram часто требует вход — бот отвечает «пришлите сам
ролик файлом». Скачанный или присланный боту пример удаляется сразу после анализа, хранится только DNA (см.
`docs/legal/privacy.*.md`).

## Этап 23 — субтитры не закрывают лицо, чистый bold_pop, музыка в режиме примера

```bash
node bin/vedit.mjs render <job_id> [--workers 1]            # avoid_face включён во всех пресетах по умолчанию
npx tsx tests/caption-check.ts --project workspace/<job>/design/<id> --video workspace/<job>/output_<id>.mp4 \
    --rough workspace/<job>/rough_<id>.mp4 --sheet sheet.jpg     # проверка: лица на готовом ролике × рамки субтитров
```

**Лица по кадрам** (`src/design/faces.ts`) — режим `faces` того же сайдкара `tools/matte/vedit_matte.py`: MediaPipe Tasks
FaceDetector, модель BlazeFace short-range (Apache-2.0, ~230 КБ, скачивается в `tools/matte/models` при первом запуске
или `vedit_matte.py model`), 8 кадров/с по **черновой нарезке** (то есть по кадру после кропа и наездов), весь кадр + квадратные
окна высокого кадра (BlazeFace сжимает вход до 128×128), NMS. Трек сглаживается: провалы ≤ 0.5 с заполняются соседями,
маленькое неуверенное «лицо» рядом с уверенным (значок на микрофоне, фигурка на полке: score 0.5–0.75, треть ширины лица)
выкидывается. Кэш `design/<id>-faces/faces_<хэш>.json` (содержимое нарезки + параметры + текст скрипта); 30 с рилса ≈ 3–6 с.
Без сайдкара — **запаска**: точка фокуса сцен (`scenes.json`) через ту же математику кропа, что в нарезке (auto_face или
центр, последний наезд), размер лица по типу плана; совсем без данных вертикальный ролик считает лицо «типичным» для
говорящей головы (верх-центр, в сплите — нижняя половина) — только для субтитров. В сплите боксы переводятся в кадр
композиции: нижняя половина с `object-position` или плашка вырезанного спикера (`y0` из статистики сайдкара).

**Где встаёт страница** (`src/design/placement.ts`, чистая функция, вызывается из `buildLayout`): препятствия — все лица
за время показа страницы, если по горизонтали пересекаются с текстом, с запасом сверху max(6 %, 0.3 высоты лица) (лоб,
волосы; в сплите 8 %) и 6 % снизу (подбородок); плюс хук на стыке в сплите; для титров и аутро — уже поставленные
субтитры. Блок всегда внутри безопасной зоны Reels: верхние 8 % и нижние 16 % кадра закрыты интерфейсом (для 16:9 — только
поле дизайна). Порядок: место пресета / DNA (`captions.anchor_y`) → ближайшее свободное место **с той же стороны лица**
(субтитры внизу — под подбородком, титр сверху — над лбом) → с другой стороны → самая большая свободная полоса → меньшее
перекрытие (и тогда страница пробует однострочный вариант меньшим кеглем, до 0.6 базового). **Гистерезис**: страница
остаётся там же, где предыдущая, пока место свободно; новое место выбирается сразу на ~3 с вперёд (объединение лиц следующих
страниц), поэтому субтитры не «съезжают» каждую страницу; к месту пресета (или ближе к нему) они возвращаются только на
склейке, после паузы ≥ 0.5 с или если место держалось ≥ 3 с. Переезд — короткий кроссфейд (0.1 с старая страница, 0.12 с
новая), посреди слова ничего не прыгает. Блок субтитров: ≤ 2 строк, ширина ≤ 80 % кадра. Титры, плашки (`callout`), строки
`lower` и CTA-аутро проходят ту же логику. `layout.json` хранит `anchorY`/`place` каждой страницы и сводку `faces`
(источник, сколько страниц сдвинуто). Выключить — `design.captions.avoid_face: false`.

**bold_pop** стал спокойнее: кегль 60 px при 1080 (было 68), обводка 3 px полупрозрачная (`rgba(0,0,0,0.85)`, было 6) +
мягкая тень, ≤ 3 слов на страницу, якорь 0.75 (нижняя треть). Значения из DNA примера в режиме примера не трогаются.

**Музыка в режиме примера** (`src/audio/musicdetect.ts`). Gemini «услышал» подложку в примере без музыки
(`ref_reference.mp4`) — теперь решает локальный замер. Главный признак — **тональность тихих моментов**: 15 % самых тихих
окон по 256 мс (микропаузы, согласные, хвосты слов — там голос не маскирует подложку), лог-спектр 60–2000 Гц против
скользящей медианы по 9 бинам: ноты и аккорды торчат пиками, комнатный шум и дыхание гладкие. Тишина между словами
(≥ 35 дБ ниже слов, если пауз ≥ 0.8 с) — довод против музыки; громкие паузы доводом «за» не считаются (на подкасте их
заполняет второй собеседник). Суббас и ритм нижней полосы — в отчёте, но не голосуют (не разделили наши ролики).
Правило (`decideMusic` в `src/style/extract.ts`): уверенное «есть»/«нет» по звуку побеждает Gemini; неясно → без музыки,
кроме случая «Gemini слышит музыку **и** звук к ней склоняется». Старые профили в кэше при следующем обращении
перемеряются, если файл примера под рукой; без файла и без замеров — без музыки. В рендере режим примера решает музыку
сам (`mapping.audio.music`), а не `music.enabled` из плана, составленного по старой DNA.

**Подложка в обычном монтаже** (`src/audio/mix.ts`, `src/audio/beats.ts`). Было: сайдчейн-компрессор по голосу — на
джамп-катах он качал подложку на каждом слоге (разброс уровня под речью 9–12 дБ), а сама подложка сидела на −29…−31 дБ

басу); фейды qsin (вход 0.8 с, выход — длина последнего клипа, 0.8–3.5 с); вместо второго динамического `loudnorm` —

Ограничения: BlazeFace short-range рассчитан на лица ближе ~2 м — мелкие лица общих планов может не найти; профиль в три
четверти и сильно наклонённая голова находятся хуже; в сплите, когда лицо занимает всю нижнюю половину, субтитры уходят на
стык и закрывают низ верхней панели; локальный детектор музыки может ошибиться на тональном шуме (гул сети, вентилятор) и
на звуковых эффектах — вжухи поднимают тональность до «неясно»; запаска по сценам грубая (один бокс на клип).

## Этап 24 — загрузка видео в бота: ссылки, форматы телефонов, локальный Bot API

Главная причина «скинул файл — бот не сделал»: облачный Bot API отдаёт боту файлы только **до 20 МБ**, а видео с
телефона почти всегда больше. Теперь:

- **Ссылка вместо файла.** Любое сообщение со ссылкой (в режиме монтажа или просто так) — это загрузка, как файл:
  Google Диск (в т.ч. страница «не удалось проверить на вирусы» у больших файлов), Яндекс Диск (файл или **папка** —
  берутся все видео из неё), Dropbox (`?dl=1`), прямая ссылка на видеофайл, YouTube / Shorts / Instagram / TikTok / VK /
  Rutube — через yt-dlp (`VEDIT_YTDLP`, на сервере ставит `setup-ubuntu.sh`). Лимит `VEDIT_LINK_MAX_MB` (2048),
  таймауты (60 с без данных, всего `VEDIT_LINK_TIMEOUT_MIN`, 30 мин), прогресс в сообщении «⬇️ Скачиваю видео по
  ссылке… 45 МБ из 120 МБ» с кнопкой «🛑 Отменить загрузку» (и `/cancel`), каждый файл проверяется ffprobe (страница,
  архив, звук без видео — отказ понятными словами). Та же ссылка второй раз не скачивается. Слова рядом со ссылкой,
  похожие на задачу («сделай 2 рилса по 20 секунд»), запускают монтаж после скачивания, как подпись к видео.
  Код: `src/ingest/links.ts`.
- **Понятный отказ.** На файл больше лимита бот отвечает: «Файл 87 МБ, а Telegram даёт боту скачивать файлы только до
  20 МБ — пришлите ссылку на видео (Google Диск / Яндекс Диск / Dropbox / YouTube) или сожмите видео. Ссылку просто
  вставьте сообщением.» (узб./англ. — так же). Ошибки ссылок: «Ссылка закрыта. Откройте доступ «всем, у кого есть
  ссылка»…», «Это ссылка на папку…», «По ссылке не видео…», «Видео по ссылке слишком большое…».
- **Загрузки в фоне.** Скачивание файлов и ссылок больше не держит цикл бота: другие пользователи обслуживаются сразу,
  загрузки одного пользователя идут по очереди. Текст задачи или ▶️, присланные во время загрузки, ждут её окончания
  (видео, затем «сделай рилс» — монтаж увидит видео). Карточка — одна на пачку, через `albumDelayMs` после *последнего
  скачанного* файла (раньше таймер мог сработать посреди пачки и подпись-задача уходила с одним видео).
- **Форматы.** Принимаются видео, кружки (`video_note`), анимации (GIF/MP4 без звука), документы `video/*`, с
  расширением в любом регистре (`IMG_0001.MOV`, `.mkv`, `.3gp`, `.mts`, `.ts`…) и `application/octet-stream` без
  расширения (проверяет ffprobe). Ingest и склейка: iPhone HDR (HEVC 10 бит HLG/PQ) тонмапится в SDR BT.709 (zscale +
  mobius; без zscale хотя бы снимаются HDR-теги), поворот (displaymatrix 90/180/270) — автоповорот, переменная частота
  кадров → 30 к/с, 4K 60 к/с → 1920 по длинной стороне, клип без звука получает тишину, обложка-картинка (attached_pic)
  не принимается за видеопоток.
- **Прочие ошибки потока:** ▶️ дважды (или ▶️ на старой карточке) — одна задача, тост «Эта карточка уже использована»;
  «🎬 Монтаж» заново — новая карточка, а не правка старой где-то вверху чата; фото посреди монтажа — «Фото в монтаж
  пока не добавляю — пришлите видео» (а не молча «фото для аватара»); перезапуск бота посреди пачки — карточка
  приходит после старта; 🏀 на пачке из нескольких видео склеивает все (раньше брался только последний); хайлайты без
  игровых моментов в выбранной ленте (редактор выкинул всё) — обычный монтаж вместо «refusing to write invalid edl.json»;
  ошибка скачивания из Telegram — «Не получилось получить файл из Telegram. Пришлите его ещё раз» (а не «не получилось
  сделать ролик»).

### Локальный Bot API: файлы до 2 ГБ

С [telegram-bot-api](https://github.com/tdlib/telegram-bot-api) в режиме `--local` бот получает файлы до 2000 МБ прямо
с диска (getFile отдаёт абсолютный путь — бот копирует файл; если путь не наш — пробует HTTP `/file/bot…`) и отправляет
до 2000 МБ. Включается переменной `TELEGRAM_API_BASE=http://127.0.0.1:8081` (лимиты переключаются сами).

Что сделать владельцу (один раз):
1. На https://my.telegram.org → «API development tools» создать приложение (любое название) и взять **api_id** и
   **api_hash** — они от аккаунта Telegram, не от бота; никому не передавать.
2. На сервере: `sudo TELEGRAM_API_ID=… TELEGRAM_API_HASH=… bash /opt/vedit/app/deploy/telegram-bot-api.sh` — соберёт
   сервер из исходников (на 1 OCPU 30–60 мин), поднимет `telegram-bot-api.service` (пользователь `vedit`, только
   127.0.0.1:8081, файлы в `/opt/vedit/tg-bot-api`, чистка старше 2 дней) и drop-in для `vedit-bot.service`.
3. Перевести бота: `sudo bash /opt/vedit/app/deploy/telegram-bot-api.sh --switch` — `logOut` бота в облаке (после этого
   облако ~10 минут не принимает бота — это нормально), `TELEGRAM_API_BASE` в `/opt/vedit/bot-api.env`, рестарт бота.
   Назад в облако: `curl -s http://127.0.0.1:8081/bot<TOKEN>/logOut; sudo rm /opt/vedit/bot-api.env; sudo systemctl restart vedit-bot`.

Тесты: `tests/stage24-uploads.test.ts` (ссылки через локальный http-сервер: Google Диск с подтверждением, закрытый
файл, папка; Яндекс Диск файл/папка; Dropbox; прямая; страница/мусор/слишком большой/зависла/отмена; локальный
Bot API; бот: пачка из 4 файлов с медленным скачиванием → одна карточка, текст во время загрузки, два пользователя
одновременно, ▶️ дважды, формы видео, точный текст про 20 МБ, ссылка → карточка, ссылка + задача, /cancel и 🛑,
фото посреди монтажа, перезапуск посреди пачки, 🏀 на пачке).

   «в 2–3 раза» → «в два-три раза», «2024-го / 2025-м / 1990-х / 90-е», «Q3» → «третий квартал», «в Q3 2025» → «в третьем
   квартале две тысячи двадцать пятого года», «18 октября», «10:30», «+45%», «−12%»; «ИИ-кодинг» → «И-И кодинг»;
5. ударения — знак U+0301 на словах из списка `stress`, **по умолчанию выключено**: проверка на Gemini (5 намеренно
   неверных ударений, «слушатель» Gemini называл ударный слог) — острое ударение сработало 1 раз из 5, «+» — 0 из 5;
   `VEDIT_TTS_STRESS=1` включает.

**Один дубль.** Вся озвучка `make` идёт одним запросом (абзац на бит, к стилю добавляется «пауза между абзацами»), дубль
режется на биты **по словам**: маленький whisper (`ggml-base`, ~3–7 с на 40 с речи, `VEDIT_TAKE_ALIGN_MODEL`,
`VEDIT_TAKE_ALIGN=off`) размечает слова, они выравниваются с текстом по каноническим произносимым формам, граница абзаца
ставится между его последним словом и первым словом следующего и подтягивается к паузе рядом (`src/voice/align.ts`).
Запасной путь — **по паузам** (`src/voice/take.ts`: паузы ≥ 120 мс, динамическое программирование по концам
предложений, у концов абзацев пауза весит в 1,6 раза больше, проверка правдоподобия долей), последний — запрос на бит
(`VEDIT_TTS_TAKE=line`). Паузы одни не справляются: gemini-3.8-flash-lite-tts проговорил два абзаца без паузы и
остановился на двоеточии — «Причина в выручке» уехала в предыдущий бит (WER по битам 6.0 %; по словам — 0.9 %). Зачем один
дубль: у бесплатного ключа **gemini-3.8-flash-tts — 10 запросов в сутки** (проверено 18.10.2026: «limit: 10 requests per
day on Free Tier»), а старая схема тратила 7 на ролик; к тому же одна интонация на весь ролик.

Типичные ошибки whisper: бренды кириллицей или по буквам («Грок», «ЛЛМ», «LAMA»), версии («GPT-3 и 5» вместо GPT-3.5),
редкие слова («дрейв» вместо «дрейф» — не исправляется: не имя). Живой прогон `vedit understand` на склейке загрузок
пользователя (`20261014-122a1b`, 56 с): правка нашла «Энтропик» → «Anthropic» в субтитрах, $0.0004, остальное не тронула.
Отсюда:

- **Правка распознанного** (`VEDIT_ASR_FIX=auto|off`, по умолчанию при ключе Gemini; модели `VEDIT_ASR_FIX_MODEL`,
  сначала flash-lite): один структурированный запрос на 150 фраз, модель возвращает только подстановки «фраза, неверные
  слова подряд → верные»; мы применяем их **по словам, не трогая таймкоды**: столько же слов — один к одному, меньше —
  хвост сливается в последнее слово (его интервал = объединение), больше — лишние слова едут на последнем токене; новых
  границ не появляется (тест). Знаки препинания остаются на своих словах. Кэш `workspace/_cache/asrfix/`. Сырой
  транскрипт — `transcript.raw.json`, итог правки — `understand.json → asr_fix`. Субтитры строятся из `transcript.json`,
  то есть показывают исправленные слова.
- **Подсказка для whisper** (`--prompt`): имена и термины из инструкции пользователя (CLI `-p`, задача в боте, сценарий
  аватара). Замер: подсказка с правильными именами почти не помогла («Lama» вместо «LAMA») и один раз выкинула фразу в
  начале куска, а режим «нести имена из прошлых кусков» повторял ошибки самого whisper и делал текст «списком через
  запятую». Поэтому **по умолчанию выключена**: `VEDIT_WHISPER_PROMPT=on` (только инструкция) или `carry`; инструкция
  всё равно идёт подсказкой в правку.
- **Язык каждой фразы** (смешанные ru/uz/en): whisper.cpp знает язык куска, а фраза получает свой по письменности и
  маркерам (ўқғҳ, oʻ/gʻ и узбекские служебные слова, английские служебные слова).
- **Гигиена субтитров**: заглавная буква в начале фразы, без задвоенной пунктуации; таймкоды не меняются.

### Ролики поинтереснее (`make`)

- **Длина 35–45 с**: `--seconds` по умолчанию 40; бюджет озвучки `narrationBudget` = (сек − 0,45 × битов) × 3 слова/с,
  считается в **произносимых** словах («965» — три слова); бит ≤ 20 слов, хук ≤ 10 и число/имя в первых пяти словах,
  экранная строка хука ≤ 7 слов. Проверка в коде (`pacingFindings`) уходит модели в той же одной переписке, что и клише.
- **Хук**: голос начинается сразу (0,05 с вместо 0,25), бит хука короче остальных; кадр 1 — «удар камерой» (масштаб
  118 % → 100 % с размытием) и белая вспышка, звуковой удар; второй бит (~3-я секунда) — **перебивка**: всегда whip или
  zoom + вспышка цветом акцента, подъём (riser) в него и удар; такой же подъём и удар на развязке (последний бит).
- **Музыка выбирается до композиции**: настроение директора, в выдаче Openverse отсекаются эмбиент/лоуфай/дрон/пиано, у
  скачанного трека проверяется бит (`bedStart`: 85–180 BPM, сила ≥ 0,12; до 3 кандидатов), трек стартует с сильной доли
  после вступления, **склейки сцен переносятся на доли** (`snapBeatsToMusic`: граница сдвигается к ближайшей доле, ±0,3/0,45 с,
  но не внутрь речи), голос перекладывается заново (`layVoiceover`). Уровень подложки под голосом — прежний (≈ −19 дБ).
- **Живой фон**: два мягких цветовых пятна (акцент и второй акцент) дрейфуют через весь ролик и «вздыхают» на каждой
  склейке, сетка ползёт вверх, зерно мерцает 12 к/с, по полю «statement» проходит световой блик; всё на той же paused-
  таймлайн GSAP. Ken Burns на фото, одометры цифр — как раньше.
- **Разнообразие**: каждый типографский приём (список, чат, таймлайн, сравнение, statement, цитата, большая цифра, 3D) —
  не больше одного раза за ролик (`ONCE_LAYOUTS`, повтор → заголовок или большая цифра), фото-макеты могут повторяться.

## Оценки и самопроверка (этап 28)

Петля обратной связи: человек ставит ⭐ и говорит «почему», ИИ-критик в фоне смотрит каждый готовый ролик и ставит свои
оценки, админ видит обе стороны рядом — и случаи, где они расходятся.

```bash
node bin/vedit.mjs feedback report --days 30          # сводка как в /admin → 📊 Оценки + docs/feedback-report.md
node bin/vedit.mjs feedback review out.mp4 --kind make --task "тема ролика"   # критик на любом файле (JSON)
```

**После оценки (бот).** Кнопки 1⭐…5⭐ под результатом не просто сохраняют число — то же сообщение превращается в
вопрос с кнопками-причинами (можно несколько, повторное нажатие снимает ✓):

- 1–3⭐: «Спасибо за оценку ⭐⭐. Что не получилось? Отметьте одно или несколько:» — [Субтитры] [Картинки не по теме]
  [Нет динамики / скучно] [Голос / произношение] [Музыка / звук] [Ошибка в тексте / фактах] [Обрезано не там]
  [Долго ждать] [Другое] [✅ Готово];
- 4–5⭐: «Спасибо за ⭐⭐⭐⭐! Что понравилось больше всего? Можно несколько:» — [Хук] [Картинки] [Субтитры]
  [Динамика] [Голос] [Музыка] [Всё отлично] [✅ Готово].

После «Готово»: «Можно добавить пару слов или голосовое — или нажмите Готово» [✅ Готово]. Текст или голосовое в
течение 15 минут — комментарий (голосовое распознаётся whisper.cpp, ≤ 120 с: «Спасибо! Записал: «…»»); позже текст
снова обычная задача. Затем сообщение возвращается к результату (текст, «Ещё вариант / Поправить / Другой формат»), а
строка звёзд — «⭐⭐ · изменить»: нажатие снова показывает 1–5, причины сохраняются, если оценка осталась по ту же
сторону (1–3 / 4–5). Одна запись на (задача, ролик, пользователь); у результата из нескольких роликов ролик — `*`.
Все строки — ru/uz/en, `callback_data` вида `fb:<job>:t:<код>` (≤ 64 байт).

Если оценка ≤ 3⭐ и самопроверка уверена (`confidence ≥ 0.6`, критерий ≤ 2 совпадает с выбранной причиной или,
без причин, один явно худший критерий) — одна фраза: «Похоже, проблема в субтитрах. Учтём.» Неуверенный критик,
ничья или несогласие с причинами пользователя — молчание. Один раз на запись.

**Самопроверка (ИИ-критик, `src/review/self-review.ts`).** После доставки каждого результата (монтаж, хайлайты, по
примеру, по теме, правка, монтаж аватара; до `VEDIT_SELF_REVIEW_MAX=3` роликов на задачу) — в фоне, по одному, никогда
не задерживая ответ: копия 480p (короткая сторона, ≤ 24 к/с, ≤ 180 с, AAC 64k) → Gemini Files API → строгий JSON

## Без привязки к Claude (этап 29)

Каждый LLM-шаг работает на **Claude или на Gemini**: планировщик монтажа (агент с инструментами), шортлист длинного
видео, сценарий и арт-директор `make`, перевод субтитров, панели сплита, редактор хайлайтов, монолог аватара. На
сервере клиента достаточно `GEMINI_API_KEY` + `TELEGRAM_BOT_TOKEN` — ключ Anthropic не обязателен.

```bash
node bin/vedit.mjs plan <job> -p "1 рилс 30 секунд" --backend gemini   # планировщик на Gemini явно
VEDIT_LLM=gemini node bin/vedit.mjs make "тема"                         # все LLM-шаги на Gemini
```

| переменная | что делает |
|---|---|
| `VEDIT_LLM` = `auto` / `claude` / `gemini` | провайдер всех LLM-шагов; `auto` (по умолчанию) — Claude, если есть `ANTHROPIC_API_KEY` (локально — и вход Claude Code), иначе Gemini, если есть `GEMINI_API_KEY`, иначе понятная ошибка |
| `VEDIT_LLM_<ШАГ>` | один шаг: `PLANNER`, `SCRIPT`, `DESIGN`, `TRANSLATE`, `SHORTLIST`, `HIGHLIGHTS`, `AVATAR`, `PANELS` (сильнее `VEDIT_LLM`) |
| `VEDIT_LLM_FALLBACK` = `on` / `off` | сбой Claude (ключ, квота, перегрузка 429/529/503, сеть) → шаг один раз повторяется на Gemini; в лог и в `plan.json → warnings` пишется `llm_fallback`. Отказ модели, невалидный план и бюджет запаску **не** включают |
| `--backend gemini` / `VEDIT_PLANNER=gemini` | планировщик на Gemini независимо от `VEDIT_LLM` |
| `VEDIT_GEMINI_PLANNER_MODEL` | модель(и) планировщика через запятую; дальше `gemini-3.8-flash → 3.7-flash → 3.6-flash → 3.5-flash` |
| `VEDIT_GEMINI_LLM_MODEL` | то же для сценария, арт-директора, перевода, шортлиста |

**Планировщик на Gemini** (`src/plan/backend/gemini.ts`) — тот же контракт, что у бэкенда Claude API: инструменты
планировщика (`get_transcript_range`, `get_scene_details`, `preview_frame`, `validate_edl`, `submit_edl`) идут через
function calling `generateContent` (`functionDeclarations`, `toolConfig` AUTO, ответы `functionResponse` с `id`, кадры —
мультимодальной частью ответа), ход модели отправляется обратно как есть (thought signatures Gemini 3), итоговый
`PlanDraft` — `responseSchema` (контракт `format`) или вызов `submit_edl` (контракт `submit`; если API на первом запросе
не примет схему вместе с инструментами, планировщик сам переключится на него). Дальше всё общее: тот же резолвер, те же
раунды исправлений (`continue()` в том же диалоге), тот же бюджет `VEDIT_BUDGET_*` (каждый запрос оплачивается и
списывается сразу, вызовы инструментов и кадры считаются). `--effort` → `thinkingLevel` (low / medium / high). Пустой
ответ или битый вызов функции — одна подсказка «повтори»; `SAFETY` / `PROHIBITED_CONTENT` — отказ; обрезка по
`MAX_TOKENS` — повтор с 32k.

**Модели и квоты** (`src/lib/gemini-llm.ts`). 429/503, которые не прошли за 2 повтора, и 404 — следующая модель списка;
суточная квота (`…PerDay…`, «limit: 0») выключает модель до конца запуска, поминутная (`…PerMinute…`) пережидается
(`retryDelay`, у планировщика до 65 с). Плохой ключ и ошибки формы запроса (схема, mime вместе с инструментами) по
моделям не перебираются. Структурированные вызовы: `toGeminiSchema` превращает JSON Schema из zod в `responseSchema`
(OpenAPI): `$ref` разворачиваются, `anyOf` с `null` → `nullable`, `anyOf` объектов сливаются (обязательны общие поля),
`const` → `enum`, `additionalProperties` и числовые enum выкидываются, свободные словари идут JSON-строкой и
раскодируются обратно; ответ всё равно проверяет zod вызывающего. Невалидный JSON / обрезка / блок — один ремонт;
схему не принял API — повтор в JSON-режиме со схемой в промпте.

**Цены** (ai.google.dev/gemini-api/docs/pricing, проверено 2026-10-19, платный уровень, $ за 1M токенов):
`gemini-3.8-flash` и `3.6-flash` — вход 0.75, выход (с размышлениями) 3.75, кэш 0.075, **с 2027-01-01 вдвое дороже**
(учтено по дате); `3.5-flash-lite` — 0.30 / 2.50 / 0.03; `3.1-pro-preview` — 2 / 12. `gemini-3.7-flash` отвечает моделью
`gemini-3.8-flash` (`modelVersion`) и считается по её цене; `3.5-flash` в таблице цен нет — пишется без цены
(`unpriced`), не угадывается. Стоимость — в `cost.json` (`provider: gemini`) и в `plan.json`.

**Бесплатный уровень Gemini для клиентов не годится**: 20 запросов в сутки на модель
(`GenerateRequestsPerDayPerProjectPerModel-FreeTier`), а один план — 4–8 запросов. Проверка ниже исчерпала квоту
3.8-flash и 3.6-flash за час (3.7-flash и 3.5-flash-lite считаются отдельно). Клиенту — платный уровень (Tier 1) либо
Claude API основным и Gemini запаской.

**не выдержал длину** (17.6 с при запросе 30–45 с; речи в исходнике ≈20 с — Claude добрал до 29 с паузами и оставил
двойной призыв, о чём честно написал). dd70df: оба плана валидны и связны; Claude взял мысль сильнее — «если мы не
станем мультипланетным видом, уничтожение жизни на Земле неизбежно» → полмиллиарда лет → погибшие цивилизации;
Gemini — «мозг 10 Вт против 10-мегаваттного кластера GPU, ИИ идёт грубой силой — путь в никуда», хороший парадокс, но с
повтором в начале («…потребляют всего 10 Вт» и сразу «…потребляют менее 10 Вт»). Сценарий `make`: у Claude свежие цифры
2025 года (OpenAI $500 млрд, Anthropic $61.5 → 183 млрд, 800 млн пользователей ChatGPT в неделю) и ответ на «почему»;
у Gemini — данные 2024 года (оценка $157 млрд, Claude 3.5 Sonnet), зато без клише и с ясной концовкой «прибыль забирают
производители чипов»; в обычном `make` факты приходят из трендов (Gemini + Google Search), так что возраст знаний
модели закрывается. Арт-директор у обоих — валидный дизайн с разными раскладками на каждый бит.

Запаска проверена живьём: `ANTHROPIC_API_KEY` с неверным ключом → `401 invalid x-api-key` → «⚠ Claude недоступен … → повтор
на Gemini» → план продолжился на Gemini (в этот раз упёрся в суточную квоту бесплатного уровня — см. выше).

**Вывод.** Gemini — полноценная замена: все планы валидны с первого раза, стоимость в 3–6 раз ниже. Claude точнее держит
длину и выбирает хук. Для клиентов по умолчанию: **Gemini 3.8-flash на платном уровне**, когда ключа Anthropic нет
(один ключ на всё: план, сценарий, кадры, голос, тренды); если качество важнее цены — Claude API основным, Gemini
запаской (`VEDIT_LLM_FALLBACK=on`, по умолчанию).

**Ограничения.** Gemini охотнее ходит в инструменты (кадры, диапазоны): больше запросов и дольше (85–150 с против
30–45 с); длину ролика держит хуже, когда исходной речи мало; цен 3.7-flash / 3.5-flash нет в прайсе; бесплатный
уровень — 20 запросов в сутки на модель; вызовы из `src/bot/*` идут через общий `auto` / `VEDIT_LLM` (пошаговые
`VEDIT_LLM_<ШАГ>` там не различаются, пока бот не передаёт имя шага).

## Модули и промпты

Проект собран из сменных модулей; `vedit modules` показывает, какой бэкенд активен, готов ли он на этой машине и
сколько раз за окно (по умолчанию 30 дней) модуль реально отработал, сколько упал и сколько стоил — по `job.json`
и `cost.json` задач в `workspace/`. Так решается, что в ходу и что можно убрать:

```bash
node bin/vedit.mjs modules            # таблица
node bin/vedit.mjs modules --licenses # плюс зависимости и лицензии каждого бэкенда (для due diligence)
node bin/vedit.mjs modules --json --days 90
```

Реестр — `src/modules.ts`: для каждого модуля этап, способ выбора бэкенда (флаг/переменная), бэкенды с зависимостями
и лицензиями, `probe()` готовности и правило, какие записи `cost.json` ему принадлежат. Модули: ingest, asr, speakers,
scenes, vision, highlights, style, planner, shortlist, cut, translate, render, make, voice, avatar, bot, users, feedback, cli.

Та же команда печатает **пресеты** (`presets/*.json` плюс встроенные; битый файл показывается с ошибкой, а не
пропадает) и **лимиты**: бюджет планировщика ($1.50 / 240 с / 12 запросов / 2 ремонта / 16 инструментов / 6 кадров),
пороги длинного видео (250 фраз, 60k токенов, 24 окна), сжатие пака (40k токенов), порог шота (0.2), чанк
анализа (180/300 с), кусок речи whisper (28 с), память на воркер рендера, лимиты файлов бота — у каждого значение,
умолчание и откуда оно берётся (флаг, переменная окружения или код). Бюджет переопределяется переменными
`VEDIT_BUDGET_USD / WALL_S / CALLS / REPAIRS / TOOL_CALLS / FRAMES` (см. `.env.example`); флаги `--budget`,
`--max-repairs`, `--frames` сильнее переменных. Неверное значение переменной — ошибка, а не тихий откат к умолчанию.

Промпты моделей лежат в `prompts/*.md`, не в коде (`src/lib/prompts.ts`): `planner.system` (замороженный системный
промпт планировщика), `planner.task/repair/revise/submit/agent/nudge*`, `translate.*`, `shortlist.*`,
`vision.gemini.*`, `vision.agy.user`, `events.*` (события спорта), `highlights.*` (редактор хайлайтов), `style.dna.*` (Style DNA примера), `review.*` (ИИ-критик готового ролика, этап 28). Файл — шаблон с `{{переменными}}`; строки-комментарии `<!-- … -->` до модели не
доходят. `PROMPT_VERSION` в `plan.json` = базовая версия + хэш всех файлов, так что правка промпта видна в отчётах
без ручного бампа.

## Известные ограничения и бэклог

- `auto_face` — один статичный кроп на клип по точке фокуса от Gemini; если спикер ходит по кадру внутри клипа, слежения нет (нужна покадровая детекция лиц). Со стабом — центр-кроп.
- Gemini-провайдер проверен офлайн-тестами с подменённым `fetch`; живой прогон на реальном ключе ещё не делался.
- Antigravity CLI: живой прогон упёрся в сломанный хук плагина `googlecloudtools.datacloud_telemetry` в `~/.gemini/config`
  (кавычки в пути к `telemetry_hook_bundle.js`) — он блокирует все инструменты агента, включая просмотр файлов.
  Лечится отключением плагина в настройках Antigravity (`"enabled": false` в `~/.gemini/config/config.json`).
  Gemini CLI (`@google/gemini-cli`) с бесплатным входом Google больше не работает (`UNSUPPORTED_CLIENT`,
  Google переводит на Antigravity), поэтому бэкенда под него нет.
- Оформление bold_pop (2026-10-13): титр в карточке, подложка под строками субтитров (`captions.backing`), затемнение нижней трети (`captions.shade`), титр уходит под лицо, если лицо стоит высоко (`titles.avoid_face` по `scenes[].focus`), лёгкий unsharp в нарезке при апскейле ≥1.25× (9:16 из 1080p). Проверка caption-zone сделана на этапе 23 (субтитры, титры и аутро обходят лица); «fill»-анимация слова, intro-карточка — в бэклоге; аутро-CTA есть.
- Перевод субтитров даёт пословную подсветку по пропорции длины слов (не по речи) — для переведённых субтитров синхрон приблизительный.
- Рендер на Windows идёт скриншотами (~17 fps при 3 воркерах); на машине с 8 ГБ RAM — 1 воркер. Прод-рендер — на Linux (beginframe) с ≥16 ГБ.
- Remotion-адаптер к `OverlayRenderer` не написан (только прототип в `tools/remotion-overlay/`).
