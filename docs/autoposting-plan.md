# Автопостинг и «🗓 Контент-план»: план (этап 32)

Дата исследования: 19–20 октября 2026. Для Instagram, YouTube и Telegram я читал официальную документацию. Сайты developers.tiktok.com и dev.vk.com в день проверки не открывались, поэтому разделы про TikTok и VK собраны из выдержек официальных страниц, найденных поиском, и из вторичных источников. Такие места помечены ⚠.

Главная задача — экономить автору время. Бот сам предлагает темы, делает видео и готовит подпись. Публикация — одно нажатие или заранее выбранное время. **Без подтверждения человека ничего не публикуется.**

**Плюсы посредника:** работает через день, а не через месяц ревью. Аудит TikTok, App Review Meta и квоту YouTube берёт на себя сервис. Публичный хостинг видео тоже его забота.
**Минусы:** платить за каждый профиль; ещё одна сторона получает токены пользователей (это нужно указать в политике конфиденциальности); VK не поддерживает никто; зависимость от чужого API.

**Прямые API.** Плюсы: бесплатно и полный контроль. Минусы: нужен публичный HTTPS для OAuth-callback и для ссылок на видео (IG `video_url`, TikTok `PULL_FROM_URL`); у бота сейчас только long-polling. На каждую платформу — отдельное ревью: 1–6 недель и риск отказа.

## 3. Рекомендация

### Бета (сейчас, Аброр и тестировщики)
1. **Telegram-канал — уже работает** (этап 32): `/connect_channel`, публикация после подтверждения, планирование.
2. **Instagram, TikTok, YouTube — вручную в один шаг.** Кнопка «📥 Для Instagram / TikTok / YouTube» присылает памятку по форматам, готовую подпись с хэштегами отдельным сообщением (удобно копировать) и файл без пережатия. Запланированный пост без подключённого канала превращается в напоминание с этим же пакетом в выбранное время.
3. Чтобы Аброр публиковал напрямую в **свои** аккаунты, нужен один из двух путей:
   - **(а) свои приложения в режиме разработки.** Meta — Standard Access, его аккаунт в роли приложения, без ревью. YouTube — проект в Testing, перелогин раз в 7 дней. TikTok здесь не подходит: без аудита посты приватные.
   - **(б) Upload-Post Basic за $24/мес.** Самый дешёвый способ получить Reels, Shorts и TikTok через API сразу, и он покрывает Telegram.

   Для беты я рекомендую **(б)**: он не требует публичного сервера, и после подключения заглушки `src/bot/publishers.ts` заменяются одним адаптером.

### SaaS (масштаб)
- **Подавать ревью сразу**, параллельно с бетой, потому что это самый долгий путь: Business Verification и App Review в Meta (Instagram Login, `instagram_business_content_publish`), верификация OAuth и аудит в Google, аудит TikTok Content Posting API.
- До одобрения публиковать через посредника. После одобрения переводить платформы на прямые API по одной: экономия растёт с числом профилей ($3–6 за профиль в месяц у посредника).
- Инфраструктура для прямых API: HTTPS-домен (OAuth-callback и раздача видео по подписанным ссылкам с коротким сроком жизни; для TikTok домен подтверждается в портале), веб-страница «Подключить аккаунт», политика конфиденциальности с перечнем платформ.
- VK — отдельным проектом после ответа поддержки VK о праве `video`.

## 4. Как это выглядит для пользователя (поток «контент-план»)

1. Меню → «🗓 Контент-план» (или `/plan`). При первом входе бот просит описать нишу одной фразой (например, «венчурный рынок Узбекистана»).
2. Появляется карточка плана с кнопками: ниша, темы, частота (1/2/3/5/7 идей в неделю), формат (рилс 9:16 или промо 16:9), CTA, хэштеги, время публикаций, «💡 Идеи сейчас», подключение канала, Instagram/YouTube/TikTok (пока объясняют, почему вручную), пауза.
3. **Идеи по расписанию.** Раз в неделю бот исследует тренды ниши (тот же `researchTrends`, что и в «Ролике по теме») и раскладывает N идей по неделе: первая приходит сразу, остальные — в 09:00 своего дня. В карточке идеи есть тема, факт, хук, источник и кнопки **✅ Сделать / ✏️ Изменить / ❌ Пропустить**.
4. ✅ ставит обычную задачу «Ролик по теме» с профилем бренда: формат, голос, призыв в конце. Работают те же лимиты, очередь и карточка прогресса.
5. Готовое видео приходит как обычно, а за ним — **карточка публикации**: подпись (заголовок, хук, CTA, хэштеги) и кнопки
   - 📢 Опубликовать в @канал → «✅ Да, опубликовать в @канал» / ↩️ Назад (двойное подтверждение);
   - 🕒 Запланировать — ближайшие слоты из «Времени публикаций» в пределах срока хранения файла; потом «❌ Отменить публикацию»;
   - 📥 Для Instagram / TikTok / YouTube — ручной пакет;
   - ✏️ Подпись и ✏️ Поправить видео (новая версия той же идеи с правкой).
6. После публикации бот присылает «✅ Опубликовано в @канал: ссылка», и запись попадает в `publish_log`.

**Позже, при прямых API:** выбор аккаунтов-целей на карточке, обложка (кадр или своя картинка), первый комментарий (IG `/comments`), отдельные подписи по платформам (длина и хэштеги), для TikTok — обязательный экран с ником, приватностью и согласием, со свежим `creator_info` каждый раз.

### Профиль бренда
Сейчас один профиль на пользователя (`content_plans.profile`): формат, соотношение сторон, голос, CTA, хэштеги, время публикаций. В `connected_accounts.profile` есть поле под переопределения на уровне аккаунта (например, другие хэштеги для TikTok) — оно используется вместе с прямыми API. Пресет формата Аброра (`abror_split`, docs/abror-format.md) подключается как значение `format` после того, как появится в make.

## 5. Безопасность и правила

- **Человек утверждает каждую публикацию:** «📢» и подтверждение, или «🕒» (это предварительное согласие на конкретный пост в конкретное время, и его можно отменить). Планировщик никогда не публикует видео со статусом «готово» сам — это проверяет тест.
- `connected_accounts.auto_publish` по умолчанию 0. Бот его не включает, и интерфейса для него пока нет: публикация без вопроса будет отдельной функцией с явным согласием по каждому аккаунту.
- **Подключить канал может только его администратор.** `/connect_channel` проверяет, что это канал, что бот в нём администратор с правом публикации и что **отправитель команды — creator или администратор канала**. Перед каждой публикацией права бота проверяются заново; при потере прав аккаунт помечается `error`.
- **Лимиты на аккаунт:** не больше `VEDIT_PUBLISH_DAILY_MAX` (10) публикаций в сутки и пауза 60 с между постами. Запланированный пост при превышении переносится, немедленный — отклоняется с объяснением.
- **Нет двойных постов:** все переходы статусов атомарные (`claimItem`). Публикация, прерванная перезапуском (`publishing`), не повторяется — пользователь получает «проверьте канал».
- **Токены (будущие OAuth)** хранятся только зашифрованными: AES-256-GCM, ключ `VEDIT_TOKEN_KEY` из env (`src/bot/secrets.ts`). Без ключа токены не сохраняются.
- **Права на контент:** «Ролик по теме» собирается из своих материалов, фото и музыка подбираются make с записью источника и лицензии. Видео из чужих ссылок проходят подтверждение прав (этап 30) и `/takedown`. Перед прямыми API в соцсети нужно добавить в условия пункт о том, что пользователь отвечает за публикуемое, а также раскрытие коммерческого контента (обязательно для TikTok).
- **Защита от спама и лишних расходов:** новая подборка идей не создаётся, пока без ответа лежит больше 2 × N идей. Стоимость исследования записывается в `usage` (`cp:ideas`).
- **Срок хранения:** запланировать можно не дальше `VEDIT_RETENTION_DAYS − 1` дней (максимум 7), иначе файл будет удалён очисткой до публикации. Если файла нет, пользователь получает «сделайте заново».

## 6. Модель данных (миграция 6, `src/bot/db.ts`)

- `content_plans(user PK, niche, topics JSON, per_week 1..14, enabled, profile JSON, next_ideas_at, created_at, updated_at)`
- `content_items(id, user, idea, angle (факт), hook, source, status, propose_at, card_msg_id, job → jobs.id, title, output_file, caption, scheduled_at, targets JSON [account ids], error, created_at, updated_at)`
  - статусы: `pending → proposed → accepted → ready → (scheduled →) publishing → published`, а также `skipped` и `failed`
- `connected_accounts(id, user, platform telegram|instagram|youtube|tiktok|vk, label, external_id, status active|pending|revoked|error, token_enc, refresh_enc, token_expires_at, scopes, auto_publish=0, profile JSON, error, …, UNIQUE(user, platform, external_id))`
- `publish_log(id, item, account, user, platform, trigger now|schedule|manual, status ok|failed|skipped, external_id, url, error, created_at)` — аудит каждой попытки и основа лимитов.

**Планировщик:** цикл внутри процесса `bot.contentPlanTick()` раз в 60 с (`contentPlan.tickMs`). Всё состояние хранится в SQLite, поэтому перезапуск ничего не теряет. За один проход он: (1) исследует идеи для планов с наступившим сроком (следующий срок — через неделю, при ошибке — через 6 ч); (2) отправляет карточки идей, чьё время пришло; (3) публикует посты, чьё время пришло; (4) сверяет задачи, упавшие во время простоя бота. Создание видео идёт через обычный `submit`, поэтому соблюдаются лимиты, кредиты, бюджет и общая очередь.
